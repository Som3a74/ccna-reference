جودة الخدمة (QoS) ونقل الملفات (FTP/TFTP)

نبذة سريعة

في شبكات المؤسسات، تتشارك البيانات وحركة الصوت (Voice) والفيديو (Video) نفس المسارات. لمنع تقطع المكالمات أو تأخر البيانات الحساسة، نعتمد على هندسة QoS (Quality of Service):

  • أهداف الـ QoS: التحكم في أربعة تحديات رئيسية: سعة القناة (Bandwidth)، التأخير (Delay / Latency)، تفاوت التأخير (Jitter)، ونسبة الفقد (Packet Loss). حركة الصوت (Voice) تتطلب تأخير أقل من 150ms، وتفاوت (Jitter) أقل من 30ms، وفقد أقل من 1%.
  • نماذج الـ QoS: نموذج Best-Effort (الافتراضي بدون أي تمييز)، ونموذج IntServ (حجز مسبق عبر RSVP وغير عملي في الشبكات الكبيرة)، ونموذج DiffServ (النموذج المعتمد عملياً، يعتمد على تصنيف الحزم وتمييزها عند حدود الثقة Trust Boundary ثم تطبيق سلوك المعاملة في كل قفزة Per-Hop Behavior).
  • مستويات التمييز (Marking): في الطبقة الثانية CoS (3 بت في ترويسة 802.1Q). وفي الطبقة الثالثة DSCP (6 بت في حقل ToS في IPv4 تعطي 64 قيمة). أشهر قيم DSCP للامتحان: EF (Expedited Forwarding - DSCP 46) لحركة الصوت ذات الأولوية القصوى، و AF (Assured Forwarding) بأنواعه، و CS (Class Selector) المتوافق مع IP Precedence القديم.
  • آليات المعالجة: الطوابير (Queuing) مثل LLQ و CBWFQ، وتفادي الازدحام (WRED)، والتحكم في المعدل (Policing يقطع الزيادة، بينما Shaping يخزن الزيادة لتنعيم التدفق).
  • بروتوكولات نقل الملفات (File Transfer): لإدارة نسخ الـ IOS والـ Config: بروتوكول TFTP (UDP 69) البسيط بدون مصادقة، وبروتوكول FTP (TCP 20/21) بمصادقة اسم مستخدم، وبروتوكول SFTP (TCP 22) المشفر عبر SSH.

إعداد سريع (انسخ والصق)

تطبيق نموذج MQC (Modular QoS CLI) لإعطاء أولوية مطلقة لحركة الصوت (Voice EF)، وتحديد سرعة التحميل، مع إعداد نقل الملفات عبر TFTP و FTP:

! 1. الخطوة الأولى: تصنيف الحزم (Class-Map)
class-map match-any VOICE-TRAFFIC
 match ip dscp ef
 match protocol rtp audio

class-map match-any MISSION-CRITICAL
 match ip dscp af31 af32

! 2. الخطوة الثانية: تطبيق السياسات وسلوك الطوابير (Policy-Map)
policy-map WAN-EDGE-QOS
 class VOICE-TRAFFIC
  priority percent 30
 class MISSION-CRITICAL
  bandwidth percent 40
 class class-default
  fair-queue

! 3. الخطوة الثالثة: تطبيق السياسة على المنفذ (Service-Policy)
interface GigabitEthernet0/1
 service-policy output WAN-EDGE-QOS

! 4. إعدادات حساب FTP لنقل ملفات النظام
ip ftp username backup_user
ip ftp password CiscoPass123!
ip tftp source-interface GigabitEthernet0/0

الإعداد خطوة بخطوة

class-map MQC Step 1: Traffic Classification

Router(config)# Exam PT ✔

الصيغة:

class-map [match-all | match-any] <class-map-name>
 match ip dscp <dscp-value>
 match access-group <acl-number-or-name>
 match protocol <protocol-name>

الفرق بين match-all و match-any:

  • match-any: الحزمة تعتبر مطابقة لو حققت أي شرط واحد من الشروط المكتوبة (مثل بوابة OR).
  • match-all: الحزمة لازم تحقق كل الشروط المكتوبة معاً (الوضع الافتراضي، مثل بوابة AND).

الشرح: الخطوة الأولى في هيكلية MQC هي تعريف أنواع الترافيك اللي عايز تطبق عليها قواعد معينة، سواء بمطابقة قيمة DSCP، أو بواسطة Access-List، أو بنوع البروتوكول عبر NBAR.

policy-map MQC Step 2: Action & Queuing

Router(config)# Exam PT ✔

الصيغة:

policy-map <policy-map-name>
 class <class-map-name>
  priority {bandwidth-kbps | percent <percentage>}
  bandwidth {bandwidth-kbps | percent <percentage>}
  police <cir-bps> [conform-action transmit] [exceed-action drop]
  shape average <cir-bps>
  set ip dscp <dscp-value>

الأوامر المهمة داخل الـ Policy-Map:

  • priority: تفعيل طابور الأولوية المطلقة (Strict Priority Queue / LLQ) المخصص للصوت.
  • bandwidth: ضمان حد أدنى من سرعة الخط لفئة معينة (CBWFQ) في أوقات الازدحام.
  • set ip dscp: تمييز الحزم وتغيير قيمة الـ DSCP (Marking).
  • police: تحديد السرعة بالقص الفوري للزيادة (Policing).
  • shape average: تحديد السرعة بتأخير وتخزين الزيادة لتنعيم التدفق (Shaping).

service-policy MQC Step 3: Interface Application

Router(config-if)# Exam PT ✔

الصيغة:

interface <interface-id>
 service-policy {input | output} <policy-map-name>

الشرح: الخطوة الأخيرة لتفعيل خطة الـ QoS بربطها بمنفذ الراوتر أو السويتش. اختر output للترافيك الخارج من الراوتر للـ WAN (وهو الأكثر استخداماً للطوابير والـ Shaping)، أو input للترافيك القادم من الشبكة الداخلية عند تطبيق الـ Classification والـ Policing.

mls qos trust Switch Trust Boundary

Switch(config-if)# Exam PT ✔

الصيغة:

interface <interface-id>
 mls qos trust {cos | dscp | device cisco-phone}

الشرح: حدود الثقة (Trust Boundary). افتراضياً السويتش لا يثق في العلامات القادمة من أجهزة الكمبيوتر ويعيد ضبط الـ CoS/DSCP إلى 0. عند توصيل تليفون آي بي (IP Phone)، نستخدم mls qos trust device cisco-phone ليثق السويتش في ترافيك التليفون بينما يعيد تصفير ترافيك الكمبيوتر المتصل خلف التليفون.

copy ... tftp: / flash: TFTP Backup & Restore

Router# Exam PT ✔

الصيغة:

! أخذ نسخة احتياطية من ملف الإعدادات إلى سيرفر TFTP
copy running-config tftp:

! تحميل نسخة نظام تشغيل IOS من سيرفر TFTP إلى ذاكرة الفلاش
copy tftp: flash:

الشرح: بروتوكول TFTP يعمل على منفذ UDP 69 بدون كلمة مرور ولا تشفير. يتم استخدامه بكثرة في معامل الـ CCNA وسيسكو لسهولته وسرعته في نقل نسخ الـ IOS والـ Config.

copy ... ftp: / flash: FTP Operations

Router# Exam PT ✔

الصيغة:

! إعداد اسم المستخدم وكلمة المرور الافتراضية للـ FTP في وضع الكونفيج
ip ftp username <username>
ip ftp password <password>

! النقل من أو إلى سيرفر الـ FTP
copy running-config ftp:
copy ftp: flash:

الشرح: بروتوكول FTP يعمل عبر TCP (المنفذ 21 لقناة الأوامر والتحكم Control، والمنفذ 20 لقناة نقل البيانات Data). يتطلب تسجيل دخول باسم مستخدم وكلمة مرور، لكنه غير مشفر.

ip tftp / ftp source-interface Source Interface Selection

Router(config)# PT ✔

الصيغة:

ip tftp source-interface <interface>
ip ftp source-interface <interface>

الشرح: تحديد المنفذ الفيزيائي أو المنطقي (مثل Loopback0) الذي سيتم استخدامه كـ Source IP عند الاتصال بسيرفر الـ TFTP أو الـ FTP لتفادي مشاكل الحماية وتوجيه المسارات.

فحص الأعطال (Troubleshooting)

  • تقطع في مكالمات الـ VoIP وسقوط حزم الصوت:
    1. تأكد من تطبيق Strict Priority (LLQ) لحركة الصوت (priority) وليس مجرد bandwidth عادي.
    2. تأكد من عدم تجاوز حركة الصوت للـ Bandwidth المحدد لها في الـ Priority Queue؛ لأن الترافيك الزائد عن حد الـ Priority يتم إسقاطه لتفادي حرمان باقي الترافيك (Starvation).
    3. تأكد من مطابقة قيمة DSCP الصحيحة (EF = 46) ومن عدم وجود سويتش غير موثوق به في المسار يقوم بتصفير الـ DSCP إلى 0.
  • الـ Policy-Map لا تطابق أي حزم (0 packets matched):
    1. افحص المنفذ المطبق عليه: هل السياسة مطبقة input والترافيك خارج output؟
    2. افحص شروط الـ Class-Map: إذا كانت match-all فقد تكون الحزم تحقق شرطاً دون الآخر. حولها إلى match-any إن أردت مطابقة أي شرط.
    3. إذا كنت تطابق باستخدام Access List، تأكد من وجود permit للترافيك المستهدف داخل الـ ACL.
  • فشل نقل الملفات عبر TFTP أو FTP:
    1. تأكد من وصول البينج (Ping) لسيرفر الملفات ومن عدم حظر المنافذ: UDP 69 للـ TFTP و TCP 20/21 للـ FTP.
    2. إذا كان الراوتر يرسل من منفذ غير متوقع، حدد المنفذ باستخدام ip tftp source-interface.
    3. في بروتوكول FTP، تأكد من صحة اسم المستخدم وكلمة المرور المحددين عبر ip ftp username.

أخطاء شائعة وفخاخ الامتحان

  • الفرق الجوهري بين الـ Policing والـ Shaping للامتحان:
    الخاصية Traffic Policing Traffic Shaping
    معالجة الترافيك الزائد إسقاط فوري (Drop) أو إعادة تمييز (Remark). تخزين مؤقت في طابور (Buffer / Delay).
    شكل موجة التدفق مسننة غير منتظمة (Sawtooth profile). ناعمة ومستمرة (Smooth profile).
    الاتجاهات المدعومة متاح في الدخول والخروج (Inbound & Outbound). متاح في الخروج فقط (Outbound ONLY).
  • فئات وقيم DSCP الأساسية للامتحان:
    • Default: DSCP 0 (Best Effort).
    • EF (Expedited Forwarding): DSCP 46 (بالنظام الثنائي: 101110) - مخصص لحزم الصوت Voice Payload.
    • AF (Assured Forwarding): مقسم إلى 4 فئات (Classes 1-4) و 3 مستويات لاحتمالية الإسقاط (Drop Precedence 1-3). مثلاً:
      • AF31: الفئة 3، احتمالية إسقاط منخفضة (Lowest Drop).
      • AF33: الفئة 3، احتمالية إسقاط مرتفعة جداً (Highest Drop).
    • CS (Class Selector): القيم من CS0 إلى CS7، حيث CS = IP Precedence * 8.
  • معادلة وجدول قيم AF (Assured Forwarding) للامتحان:

    لحساب القيمة العشرية لأي رمز AFxy (حيث x رقم الفئة من 1 إلى 4، و y احتمالية الإسقاط من 1 إلى 3)، استخدم المعادلة البسيطة:

    DSCP Decimal = (8 * x) + (2 * y)

    مثال: قيمة AF32 = (8 * 3) + (2 * 2) = 24 + 4 = 28.

  • ظاهرة TCP Global Synchronization مقابل WRED:
    • Tail Drop (الوضع العادي بدون QoS): عند امتلاء الطابور تسقط جميع الحزم لجميع الاتصالات، مما يدفع كل جلسات TCP لتخفيض نافذة الإرسال (Window Size) في نفس اللحظة بالتزامن، فيفرغ الخط فجأة ثم يمتلئ فجأة بموجات متكررة.
    • WRED (Weighted Random Early Detection): يسقط حزم عشوائية من جلسات منفردة قبل امتلاء الطابور بناءً على علامة الـ DSCP، مما يجبر بعض الاتصالات فقط على التهدئة ويمنع حدوث التزامن الكارثي للـ TCP.
  • بروتوكولات نقل الملفات ومنافذها:
    • TFTP: UDP Port 69 (بسيط، بدون مصادقة، غير مشفر).
    • FTP Control: TCP Port 21 (مصادقة مستخدم وأوامر التحكم).
    • FTP Data: TCP Port 20 (نقل البيانات في الوضع النشط Active FTP).
    • SFTP: TCP Port 22 (مشفر بالكامل ومحمي عبر نفق SSH).

جدول مختصر

Command Mode الوظيفة (Purpose)
class-map [match-any | match-all] <name> Global config تعريف فئة تصنيف للترافيك في نموذج MQC.
match ip dscp <value> Class-map config مطابقة الحزم بناءً على علامة الـ DSCP (مثل ef أو af31).
policy-map <name> Global config إنشاء خطة سياسات لتحديد الإجراءات وسلوك الطوابير لكل فئة.
priority {bandwidth | percent} Policy-map class config منح الفئة طابور أولوية مطلقة ذو كمون منخفض (LLQ) لحركة الصوت.
bandwidth {bandwidth | percent} Policy-map class config ضمان حد أدنى من سرعة الخط للفئة في أوقات الازدحام (CBWFQ).
service-policy {input | output} <name> Interface config تطبيق سياسة الـ QoS على منفذ الراوتر أو السويتش.
show policy-map interface <int> Privileged EXEC عرض إحصائيات مطابقة الحزم ومعدل الإسقاط ونشاط الطوابير.
copy running-config tftp: Privileged EXEC أخذ نسخة احتياطية من الإعدادات إلى سيرفر TFTP (UDP 69).
copy tftp: flash: Privileged EXEC تحميل ملف نظام تشغيل من سيرفر TFTP لذاكرة الفلاش.
ip ftp username <user> Global config تحديد اسم المستخدم الافتراضي لعمليات الـ FTP (TCP 20/21).
