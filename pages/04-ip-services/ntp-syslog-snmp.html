CCNA Reference

بروتوكولات NTP, Syslog و SNMP

نبذة سريعة

في إدارة ومراقبة شبكات سيسكو المؤسسية، بتعتمد العمليات اليومية والتحقيقات الأمنية على ثلاثة بروتوكولات أساسية في الطبقة السابعة:

  • NTP (Network Time Protocol - UDP 123): بروتوكول مزامنة التوقيت بدقة بالغة. توحيد الوقت إجباري عشان تقدر تربط سجلات الأحداث (Log Correlation) بين مختلف الأجهزة، وتتأكد من صلاحية الشهادات الرقمية (Certificates) وسجلات الدخول (AAA Accounting). بيستخدم مفهوم الطبقات (Stratum) من 0 إلى 15 (حيث 0 مصدر توقيت ذري أو GPS، و 1 سيرفر متصل به مباشرة)، و 16 تعني أن الجهاز غير متزامن إطلاقاً.
  • Syslog (UDP 514): بروتوكول تجميع وتوثيق رسائل النظام والأحداث. رسالة السيسلوج لها هيكل ثابت: *timestamp: %facility-severity-MNEMONIC: description. وتتدرج خطورة الرسائل في 8 مستويات من 0 (الأخطر - الطوارئ) إلى 7 (الأقل خطورة - التصحيح).
  • SNMP (Simple Network Management Protocol): بروتوكول إدارة ومراقبة الأجهزة عبر نظام مركزي (NMS). يعتمد على تبادل البيانات عبر قاعدة معلومات الإدارة (MIB) وعناوين التعريف (OID). يشمل عمليات القراءة والكتابة (GET, SET) والإشعارات الفورية كالتنبيهات غير المؤكدة (Traps على UDP 162) أو المؤكدة (Informs على UDP 162). يشمل ثلاثة إصدارات رئيسية: v1 و v2c (يعتمدان على كلمة مرور نصية Community String) و v3 (يوفر المصادقة والتشفير التام).

إعداد سريع (انسخ والصق)

تفعيل مزامنة التوقيت عبر NTP، وإرسال السجلات لسيرفر Syslog مع طابع زمني دقيق، وتفعيل SNMPv2c و SNMPv3:

! 1. ضبط المنطقة الزمنية وربط الراوتر بسيرفر NTP
clock timezone EEST 2 0
ntp server 192.168.1.100 prefer
ntp source GigabitEthernet0/0

! 2. تفعيل الطوابع الزمنية الدقيقة وإرسال السجلات لسيرفر Syslog
service timestamps log datetime msec
logging buffered 64000 informational
logging host 192.168.1.50
logging trap warnings

! 3. تفعيل SNMPv2c للقراءة فقط (Read-Only) مع استقبال الـ Traps
snmp-server community NetAdminRO RO
snmp-server host 192.168.1.50 version 2c NetAdminRO
snmp-server enable traps

! 4. إعداد SNMPv3 مشفر وآمن (AuthPriv)
snmp-server group SECURE-GRP v3 priv
snmp-server user admin1 SECURE-GRP v3 auth sha AuthPass123! priv aes 128 PrivPass123!

الإعداد خطوة بخطوة

ntp server NTP Client Mode

Router(config)# Exam PT ✔

الصيغة:

ntp server <ip-address> [prefer]

إيه اللي بنحطه مكان القيم:

  • <ip-address> = عنوان IP لسيرفر التوقيت الخارجي أو الداخلي.
  • prefer = كلمة اختيارية بتخلي الراوتر يفضل السيرفر ده عن باقي السيرفرات لو ضفت أكتر من سيرفر.

الشرح: ده الأمر اللي بيحول الجهاز لـ NTP Client عشان يسحب الوقت بانتظام من سيرفر مركزي عبر منفذ UDP 123.

ntp master NTP Server Mode

Router(config)# Exam PT ✔

الصيغة:

ntp master [stratum-number]

الشرح: بيخلي الراوتر ده نفسه يشتغل كـ NTP Master/Server ويوزع الوقت للأجهزة التانية لو مفيش اتصال بسيرفر خارجي. قيمة الـ stratum-number الافتراضية هي 8 (تقدر تحددها من 1 إلى 15).

ntp source Source Interface

Router(config)# Exam PT ✔

الصيغة:

ntp source <interface>

الشرح: بيحدد المنفذ اللي الراوتر هيستخدم الـ IP بتاعه كـ Source IP في باكتات الـ NTP المرسلة. ممارسة شائعة جداً في الشبكات الاحترافية إنك تربطه بفتحة Loopback0 عشان تضمن ثبات الاتصال حتى لو فتحة فيزيائية وقعت.

ntp peer Symmetric Active Mode

Router(config)# PT ✔

الصيغة:

ntp peer <ip-address>

الشرح: بيخلي راوترين في نفس الـ Stratum يشتغلوا مع بعض كأنداد (Peers)، بحيث أي راوتر فيهم عنده مصدر توقيت أدق يظبط الراوتر التاني، ولو المصدر وقع يتبادلوا التوقيت تلقائياً.

ntp authenticate / trusted-key NTP MD5 Authentication

Router(config)# Exam PT ✔

الصيغة:

ntp authenticate
ntp authentication-key <key-id> md5 <password>
ntp trusted-key <key-id>
ntp server <ip-address> key <key-id>

الشرح: خطوة حماية أساسية لمنع هجمات انتحال وقت الشبكة (Time Spoofing). بيشترط إن الكلاينت والسيرفر يكون عندهم نفس المفتاح المشترك المشفر بـ MD5 ونفس الـ Key ID.

clock timezone / clock set Timezone & Manual Clock

Router(config)# / Router# Exam PT ✔

الصيغة:

! في Global Configuration: تحديد المنطقة الزمنية وفرق الساعات عن UTC
clock timezone <zone-name> <hours-offset> [minutes-offset]

! في Privileged EXEC: ضبط الساعة يدوياً عند عدم توفر NTP
clock set <hh:mm:ss> <day> <month> <year>

مثال:

clock timezone EEST 2 0
clock set 14:30:00 10 October 2026

service timestamps log datetime Log Timestamp Format

Router(config)# Exam PT ✔

الصيغة:

الشرح: أمر امتحاني شهير جداً! افتراضياً، سيسكو بتعرض الوقت في السجلات كـ Uptime (المدة من وقت تشغيل الراوتر). بتنفيذ هذا الأمر، بتتحول السجلات لعرض التاريخ والوقت الفعلي بدقة أجزاء الثانية (Milliseconds).

logging host Remote Syslog Server

الشرح: توجيه رسائل السيسلوج إلى خادم سجلات مركزي (Syslog Server / SIEM) عبر منفذ UDP 514 للاحتفاظ بالسجلات على المدى الطويل.

logging trap Syslog Severity Filter

Router(config)# Exam PT ✔

الصيغة:

logging trap <level-name | level-number>

الشرح: بيحدد مستوى الخطورة للرسائل المرسلة لخادم الـ Syslog الخارجي. لما تحدد مستوى مثل warnings (4)، الراوتر هيبعت المستوى ده وجميع المستويات الأكثر خطورة منه عددياً (يعني 0، 1، 2، 3، و 4).

logging buffered RAM Buffer Storage

Router(config)# Exam PT ✔

الصيغة:

logging buffered [buffer-size] [severity-level]

الشرح: بيخزن السجلات في ذاكرة الرام (RAM) المؤقتة للجهاز، بحيث تقدر تستعرضها بأمر show logging. الحجم بالبايت (مثلاً 64000 بايت).

terminal monitor Display Logs on SSH / Telnet

Router# Exam PT ✔

الصيغة:

terminal monitor

الشرح: أحد أكبر الفخاخ العملية والامتحانية! افتراضياً، رسايل السيسلوج بتظهر فقط على شاشة الـ Console الفيزيائية ولا تظهر لجلسات الـ SSH أو Telnet عن بعد. عشان تشوف الرسايل أثناء اتصالك عن بعد، لازم تكتب هذا الأمر في وضع الـ Privileged EXEC. (لإيقافها: terminal no monitor).

الشرح: بيمنع رسائل السيسلوج المفاجئة من مقاطعة الأمر اللي بتكتبه في الـ CLI، بحيث لو ظهرت رسالة يقوم السطر بإعادة كتابة ما كنت تكتبه في سطر جديد نظيف.

snmp-server community SNMPv1 / SNMPv2c Community String

Router(config)# Exam PT ✔

الصيغة:

snmp-server community <string> {ro | rw} [access-list-number-or-name]

إيه اللي بنحطه مكان القيم:

  • <string> = كلمة السر المشتركة (Community String) بين الـ NMS والراوتر.
  • ro = صلاحية القراءة فقط (Read-Only) - الموصى بها لمنع التعديل.
  • rw = صلاحية القراءة والتعديل (Read-Write) - خطيرة وتسمح بتغيير الإعدادات.
  • [access-list] = اختياري وموصى به جداً، لتحديد أيبيهات سيرفرات الـ NMS المسموح لها فقط بإرسال استعلامات.

snmp-server host & enable traps SNMP Traps & Informs

Router(config)# Exam PT ✔

الصيغة:

! تفعيل إرسال كل إشعارات التنبيهات
snmp-server enable traps

! تحديد عنوان سيرفر الـ NMS المستلم للتنبيهات
snmp-server host <ip-address> [version {1 | 2c | 3}] <community-string-or-user> [traps | informs]

الشرح: بيرسل تنبيهات تلقائية من الراوتر لسيرفر المراقبة في حال حدوث أحداث مفاجئة (زي سقوط واجهة LinkDown أو ارتفاع حرارة المعالج). الـ Trap بيتبعت بدون انتظار رد تأكيد (Unacknowledged على UDP 162)، أما الـ Inform فيحتاج تأكيد استلام من الـ NMS (Acknowledged).

snmp-server group & user SNMPv3 Secure Configuration

Router(config)# Exam PT ✔

الصيغة:

! 1. إنشاء مجموعة بصلاحيات الأمان المطلوبة
snmp-server group <group-name> v3 {noauth | auth | priv} [read <view-name>]

! 2. إنشاء المستخدم وربطه بالمجموعة وتحديد خوارزميات التشفير
snmp-server user <username> <group-name> v3 auth {md5 | sha} <auth-pass> priv {des | 3des | aes {128 | 192 | 256}} <priv-pass>

مستويات أمان SNMPv3:

  • noAuthNoPriv: اسم مستخدم فقط بدون تشفير أو مصادقة تجزئة.
  • authNoPriv: مصادقة وتأكد من سلامة البيانات عبر (MD5 أو SHA)، لكن بدون تشفير للرسالة.
  • authPriv: المستوى الأعلى والأقوى (مصادقة عبر SHA وتشفير كامل للبيانات عبر AES).

snmp-server location / contact Device Metadata

Router(config)# PT ✔

الصيغة:

snmp-server location <building-or-rack>
snmp-server contact <admin-name-or-email>

الشرح: معلومات توثيقية تضاف لبيانات الـ MIB (System MIB) بتسهل على أنظمة المراقبة عرض مكان الجهاز في المبنى واسم المهندس المسؤول عنه.

فحص الأعطال (Troubleshooting)

  • الساعة غير متزامنة (Clock is unsynchronized / Stratum 16):
    1. تأكد من إمكانية الوصول للـ IP الخاص بسيرفر الـ NTP باستخدام أمر ping.
    2. تأكد من عدم وجود Access List أو جدار ناري يمنع حزم UDP Port 123.
    3. لو مفعل التوثيق (Authentication)، تأكد من تطابق الـ key-id والـ trusted-key وكلمة السر المشفرة تماماً.
    4. تأكد إن الراوتر مش شايف دورة توقيت (Time Loop) رفعت الـ Stratum لرقم 16.
  • السجلات مش ظاهرة على جلسة SSH أو Telnet:
    1. اكتب فوراً terminal monitor في وضع الـ Enable.
    2. تأكد إن إعداد الـ logging monitor مش معمول على مستوى خطورة مرتفع جداً يستثني الرسايل العادية.
  • خادم الـ Syslog مش بيستلم أي رسائل:
    1. تأكد من الـ Routing بين الراوتر وسيرفر الـ Syslog على منفذ UDP 514.
    2. افحص أمر logging trap؛ لو معمول مثلاً logging trap errors، رسايل الـ Warnings والـ Notifications والـ Informational مش هتروح للسيرفر إطلاقاً!
  • سيرفر المراقبة NMS عاجز عن سحب بيانات SNMP:
    1. تأكد من تطابق الـ Community String تماماً؛ فهي حساسة لحالة الأحرف (Case-Sensitive).
    2. لو في Access List مربوطة مع الـ Community، تأكد إنها بتسمح بـ IP سيرفر الـ NMS.
    3. تأكد إن منفذ UDP 161 مسموح بيه (للاستعلامات GET) ومنفذ UDP 162 مسموح بيه (للتنبيهات Traps).
    4. في SNMPv3، تأكد من صحة الـ Security Level (noAuthNoPriv / authNoPriv / authPriv) وتطابق الـ EngineID وكلمات سر الـ Auth والـ Priv.

أخطاء شائعة وفخاخ الامتحان

  • مستويات خطورة Syslog الثمانية (0 - 7): السؤال ده بيتكرر في كل امتحان CCNA بدون استثناء:
    • Level 0: Emergency (System is unusable - النظام غير صالح للاستخدام إطلاقاً)
    • Level 1: Alert (Immediate action needed - يتطلب تدخلاً فورياً)
    • Level 2: Critical (Critical condition - حالة حرجة)
    • Level 3: Error (Error condition - خطأ في أحد الوظائف)
    • Level 4: Warning (Warning condition - تحذير)
    • Level 5: Notification (Normal but significant condition - حدث طبيعي لكنه ذو دلالة زي Up/Down للواجهة)
    • Level 6: Informational (Informational message - رسالة استعلامية اعتيادية)
    • Level 7: Debugging (Debug output - مخرجات التصحيح التفصيلية)

    جملة الحفظ الذهبية: Every Alley Cat Eats Watermelon Not Ice Doughnuts.

  • فخ أرقام الخطورة (Lower is More Severe): الرقم 0 هو الأخطر، والرقم 7 هو الأقل خطورة. لو حددت logging trap 4، الجهاز هيبعت المستويات (0 و 1 و 2 و 3 و 4).
  • مفهوم الـ Stratum في NTP:
    • Stratum 0: مصدر الساعة الذرية المباشر أو الـ GPS، ولا يمكن ربطه مباشرة بكابل شبكة IP.
    • Stratum 1: أول جهاز سيرفر شبكي متصل فيزيائياً بمصدر التوقيت Stratum 0.
    • Stratum 16: يعني التوقيت غير صالح / غير متزامن إطلاقاً (Unsynchronized). أقصى Stratum صالح في الشبكة هو 15.
  • الفرق بين SNMP Trap و SNMP Inform:
    • Trap: إشعار غير موثوق به (Unreliable / Unacknowledged) بيتبعت عبر UDP 162، والراوتر مبيعرفش إذا كان وصل للـ NMS ولا لأ.
    • Inform: إشعار موثوق (Acknowledged عبر UDP 162)، الـ NMS بيرد على الراوتر بـ SNMP Response تأكيد استلام، وإذا لم يصل التأكيد يقوم الراوتر بإعادة الإرسال.
  • رموز الـ Facility الشائعة في رسائل Syslog: الـ Facility بيحدد موديول النظام اللي ولد الرسالة:
    • SYS: نظام تشغيل الراوتر (IOS System).
    • LINK: الطبقة الفيزيائية للواجهة (Interface Hardware State).
    • LINEPROTO: بروتوكول الخط في الطبقة الثانية (Data-Link Line Protocol State).
    • OSPF: رسائل وإشعارات بروتوكول التوجيه OSPF.
    • SEC: أحداث الأمن وحزم الـ IP Security.
  • بنية SNMP MIB و OID:
    • MIB (Management Information Base): قاعدة بيانات شجرية منظمة تحتوي على كل المتغيرات التي يمكن مراقبتها على الجهاز.
    • OID (Object Identifier): المعرف الرقمي الهرمي لكل متغير في الشجرة (مثلاً: 1.3.6.1.2.1.1.1 يشير إلى متغير sysDescr).
  • بورتات البروتوكولات للامتحان:
    • NTP: UDP 123
    • Syslog: UDP 514
    • SNMP Queries (Manager to Agent): UDP 161
    • SNMP Notifications (Agent to Manager - Traps / Informs): UDP 162
