شبكات VPN وحماية اللاسلكي (VPN & Wireless Security)

نبذة سريعة

يختتم قسم الحماية بموضوعين جوهريين في منهج CCNA 200-301: تأمين الاتصال عبر شبكات الإنترنت العامة باستخدام VPN (Virtual Private Network)، وتأمين وصول الهواء في الشبكات اللاسلكية Wireless Security:

  • أنواع شبكات الـ VPN الرئيسية:
    • Site-to-Site VPN: ربط فرعين ثابتين للشركة (مثل المقر الرئيسي Headquarters وفرع Branch) عبر نفق آمن فوق الإنترنت. الراوترات تعمل كـ VPN Gateways والأجهزة الداخلية لا تشعر بوجود التشفير.
    • Remote Access VPN: ربط الموظفين المتنقلين من منازلهم بشبكة الشركة، إما عبر برنامج عميل مثل Cisco AnyConnect / Secure Client (يعتمد على SSL/TLS أو IPsec)، أو بدون برنامج (Clientless SSL VPN) عبر متصفح الويب.
  • حزمة بروتوكولات IPsec (IP Security):
    • بروتوكول ESP (IP Protocol 50): يوفر التشفير الكامل للبيانات والمصادقة والتكاملية (هو الأساسي والأكثر استخداماً).
    • بروتوكول AH (IP Protocol 51): يوفر المصادقة والتكاملية فقط بدون أي تشفير للبيانات!
    • وضع النفق (Tunnel Mode): يشفر حزمة الـ IP الأصلية بالكامل ويضيف ترويسة IP جديدة (الافتراضي لشبكات Site-to-Site).
    • وضع النقل (Transport Mode): يشفر الـ Payload فقط ويحتفظ بترويسة الـ IP الأصلية (يستخدم بين جهازين مباشرة أو مع أنفاق GRE).
    • تبادل المفاتيح (IKE - UDP 500 / 4500): مفاوضات المرحلة الأولى (IKE Phase 1) والمرحلة الثانية (IKE Phase 2 / IPsec SA).
  • معايير حماية اللاسلكي (Wireless Security):
    • WPA: اعتمد على تشفير TKIP و RC4 (قديم وضعيف وملغي).
    • WPA2: يعتمد على معيار التشفير القوي AES-CCMP. هو المعيار الأكثر انتشاراً حالياً.
    • WPA3: أحدث معيار أمني؛ استبدل كلمة السر المشتركة (PSK) بتقنية SAE (Simultaneous Authentication of Equals) المحمية من هجمات التخمين دون اتصال (Offline Dictionary Attacks)، وفرض تشفير إطارات الإدارة (Protected Management Frames - PMF).
    • الفرق بين Personal و Enterprise:
      • Personal (PSK / SAE): كلمة مرور مشتركة واحدة يعرفها جميع المستخدمين.
      • Enterprise (802.1X / EAP): تسجيل دخول فردي لكل مستخدم بحسابه الخاص عبر خادم RADIUS مركزي.

إعداد سريع (انسخ والصق)

نموذج إعداد نفق GRE مشفر بـ IPsec (Site-to-Site) وإعداد شبكة WLAN آمنة على الـ WLC:

! 1. إعداد نفق GRE Tunnel لنقل ترافيك التوجيه
interface Tunnel0
 ip address 10.10.10.1 255.255.255.252
 tunnel source GigabitEthernet0/1
 tunnel destination 203.0.113.2

! 2. إعداد سياسة IKE Phase 1 (ISAKMP Policy)
crypto isakmp policy 10
 encr aes 256
 hash sha256
 authentication pre-share
 group 14
 lifetime 86400
crypto isakmp key CiscoVpnSecret#2026 address 203.0.113.2

! 3. إعداد IKE Phase 2 (IPsec Transform-Set) وتأمين النفق
crypto ipsec transform-set ESP-AES-SHA esp-aes 256 esp-sha256-hmac
 mode transport
crypto ipsec profile IPSEC-TUNNEL-PROFILE
 set transform-set ESP-AES-SHA
interface Tunnel0
 tunnel protection ipsec profile IPSEC-TUNNEL-PROFILE

الإعداد خطوة بخطوة

interface Tunnel GRE Tunnel Setup

Router(config)# & (config-if)# Exam PT ✔

الصيغة:

interface Tunnel <0-2147483647>
 ip address <tunnel-ip> <subnet-mask>
 tunnel source {<interface-name> | <source-ip>}
 tunnel destination <remote-public-ip>

الشرح: بروتوكول GRE (Generic Routing Encapsulation - IP Protocol 47) ينشئ نفقاً افتراضياً فوق الإنترنت يسمح بتمرير حزم الـ Multicast وبروتوكولات التوجيه الديناميكي (مثل OSPF). لكن عيبه القاتل أنه غير مشفر تماماً، لذلك ندمجه دائماً مع IPsec.

crypto isakmp policy & key IKE Phase 1 (ISAKMP SA)

Router(config)# & (config-isakmp)# Exam PT ✔

الصيغة:

crypto isakmp policy <1-10000>
 encr {aes [128|192|256] | 3des}
 hash {sha | sha256 | md5}
 authentication pre-share
 group {2 | 5 | 14 | 19}
 lifetime <seconds>

crypto isakmp key <shared-secret> address <peer-ip>

خماسية مفاوضات المرحلة الأولى (HAGLE):

  • H - Hash: دالة التجزئة لسلامة الرسائل (SHA-256).
  • A - Authentication: طريقة التحقق بين الراوترين (Pre-Shared Key).
  • G - Group: مجموعة تبادل مفاتيح Diffie-Hellman (DH Group 14 أو 19).
  • L - Lifetime: مدة صلاحية نفق المرحلة الأولى قبل إعادة التفاوض (افتراضياً 86400 ثانية).
  • E - Encryption: خوارزمية التشفير (AES-256).

crypto ipsec transform-set IKE Phase 2 (IPsec SA)

Router(config)# Exam PT ✔

الصيغة:

crypto ipsec transform-set <transform-name> <transform-1> [<transform-2>]
 mode {tunnel | transport}

مثال:

crypto ipsec transform-set MY-SET esp-aes 256 esp-sha256-hmac
 mode tunnel

الشرح: تحديد بروتوكولات وخوارزميات التشفير الفعلية لحزم البيانات عبر نفق الـ IPsec (غالباً نستخدم تشفير ESP مع خوارزمية AES وتجزئة SHA-HMAC).

WLC GUI: WLAN Configuration CCNA Blueprint 5.10

WLC Web GUI Exam PT ✔

خطوات إنشاء شبكة لاسلكية آمنة في واجهة WLC:

  1. Create WLAN: الدخول إلى تبويب WLANs ← اختيار Create New ← تحديد الـ Profile Name والـ SSID (اسم الشبكة المعلن للجمهور) ← ثم الضغط على Apply.
  2. General Tab: تفعيل الشبكة باختيار مربع Status: Enabled ← وتحديد الواجهة (Interface / Interface Group) لربط الشبكة بالـ VLAN المناسبة.
  3. Security Tab ← Layer 2:
    • اختيار Layer 2 Security: WPA+WPA2 (أو WPA2/WPA3).
    • اختيار نوع التشفير: تفعيل WPA2 Policy وتحديد WPA2 Encryption: AES.
    • اختيار إدارة المفاتيح (Auth Key Mgmt): تفعيل PSK وتحديد نوع التنسيق ASCII وكتابة كلمة المرور (Pre-Shared Key).
  4. Advanced Tab: تفعيل خيارات الـ FlexConnect أو الـ Client Band Select حسب الحاجة.
  5. Apply: الضغط على Apply في الزاوية العلوية لتشغيل الشبكة ونشرها فوراً عبر أجهزة الـ Lightweight APs.

فحص الأعطال (Troubleshooting)

  • نفق الـ ISAKMP لا يكتمل (حالة MM_NO_STATE أو AG_NO_STATE):
    1. تأكد من وصول البينج بين عناوين الـ IP العامة للراوترين (Peer Reachability).
    2. تأكد من فتح منافذ UDP Port 500 و UDP Port 4500 (NAT-Traversal) في الجدران النارية الفاصلة بين الموقعين.
    3. تأكد من تطابق الـ Pre-Shared Key تماماً؛ فاختلاف حرف واحد يمنع المصافحة.
    4. تأكد من تطابق إعدادات الـ ISAKMP Policy الخمسة (Encryption, Hash, Auth, DH Group, Lifetime) بين الطرفين.
  • المرحلة الأولى تعمل ولكن لا يتم تشفير أي حزم (#pkts encrypt: 0):
    1. في الـ Site-to-Site الكلاسيكي، افحص قائمة الـ Crypto ACL (Interesting Traffic)؛ يجب أن تكون معكوسة (Mirror Image) تماماً بين الراوترين!
    2. تأكد من تطابق الـ Transform-Set في المرحلة الثانية.
  • المستخدمون لا يستطيعون الاتصال بشبكة الـ WLAN الجديدة:
    1. تأكد من تفعيل خانة Status: Enabled في تبويب General للـ WLAN على الـ WLC.
    2. تأكد من ربط الـ WLAN بالـ Interface الصحيحة التي تقدم خدمة DHCP للمستخدمين.
    3. تأكد من مطابقة نوع التشفير وكلمة المرور الـ PSK.

أخطاء شائعة وفخاخ الامتحان

  • الفرق بين AH و ESP في IPsec:

    سؤال متكرر جداً: AH لا يوفر أي تشفير (No Encryption) إطلاقاً ويستخدم بروتوكول رقم 51. بينما ESP يوفر التشفير الكامل ويستخدم بروتوكول رقم 50.

  • الفرق بين WPA2 و WPA3 للامتحان:
    • WPA2-Personal: يعتمد على PSK (Pre-Shared Key) وعرضة لهجمات التخمين دون اتصال (Offline Dictionary Attacks).
    • WPA3-Personal: يعتمد على SAE (Simultaneous Authentication of Equals) عبر مصافحة Dragonfly Handshake، وهو محمي تماماً من هجمات التخمين ويوفر سرية مستقبلية (Forward Secrecy).
  • منافذ بروتوكولات الـ VPN في الفايروول:
    • IKE / ISAKMP: UDP Port 500
    • NAT-Traversal (NAT-T): UDP Port 4500
    • IPsec ESP: IP Protocol 50 (ليس بورت بل رقم بروتوكول في طبقة IP)
    • IPsec AH: IP Protocol 51
    • GRE: IP Protocol 47

جدول مختصر

Command Mode الوظيفة (Purpose)
interface Tunnel <id> Global config إنشاء واجهة نفق افتراضية منطقية (مثل GRE أو IPsec).
tunnel source <int/ip> Interface config (tunnel) تحديد المنفذ الفيزيائي أو الـ IP المصدر للنفق.
tunnel destination <ip> Interface config (tunnel) تحديد عنوان الـ IP العام للطرف البعيد من النفق.
crypto isakmp policy <n> Global config تعريف سياسة التفاوض للمرحلة الأولى IKE Phase 1 (التشفير، التجزئة، DH).
crypto isakmp key <k> address <ip> Global config تحديد كلمة السر المشتركة (Pre-Shared Key) للطرف البعيد.
crypto ipsec transform-set <name> ... Global config تحديد بروتوكولات وخوارزميات تشفير المرحلة الثانية IPsec Phase 2.
show crypto isakmp sa Privileged EXEC فحص نفق المرحلة الأولى والتأكد من الوصول لحالة QM_IDLE.
show crypto ipsec sa Privileged EXEC عرض إحصائيات الحزم المشفرة والمفكوكة في المرحلة الثانية.
