قوائم التحكم في الوصول (ACLs)

نبذة سريعة

قوائم ACLs (Access Control Lists) هي خط الدفاع الأول في راوترات وسويتشات سيسكو لفلترة حزم البيانات ومنع المرور غير المصرح به. تتكون القائمة من أسطر مرتبة (Access Control Entries - ACEs) يتم فحصها من الأعلى إلى الأسفل حتى يتحقق أول شرط:

  • أنواع الـ ACLs الأساسية:
    • Standard ACLs: تفلتر بناءً على عنوان IP المصدر (Source IP) فقط. أرقامها من 1 إلى 99 و 1300 إلى 1999 (أو بأسماء Named).
    • Extended ACLs: تفلتر بناءً على: المصدر (Source IP)، الوجهة (Destination IP)، نوع البروتوكول (TCP/UDP/ICMP/IP)، وأرقام المنافذ (Ports مثل HTTP 80 أو SSH 22). أرقامها من 100 إلى 199 و 2000 إلى 2699 (أو بأسماء Named).
  • القواعد الذهبية للـ ACL:
    • قاعدة المعالجة التتابعية (Top-to-Bottom): الراوتر يقرأ القائمة سطراً بسطر؛ وأول سطر يطابق الحزمة (First Match) ينفذ فوراً ويتوقف الفحص لباقي القائمة.
    • الرفض الضمني (Implicit Deny Any): يوجد دائماً في نهاية كل قائمة سطر مخفي يرفض كل الحزم غير المطابقة (deny ip any any). لذلك، أي قائمة لا تحتوي على سطر permit واحد على الأقل ستحظر كل الترافيك بلا استثناء!
    • أماكن التطبيق (Placement Rules):
      • Standard ACL: توضع أقرب ما يمكن للوجهة (Closest to Destination)، لأنها تطابق المصدر فقط، ووضعها قريباً من المصدر سيحرمه من الوصول لأي شبكة أخرى بالخطأ!
      • Extended ACL: توضع أقرب ما يمكن للمصدر (Closest to Source)، لإسقاط الحزم غير المرغوبة فوراً قبل أن تستهلك سعة خطوط الـ WAN وموارد المعالجة.
    • ترافيك الراوتر نفسه (Self-Generated Traffic): الحزم الصادرة من الراوتر نفسه (مثل Ping أو NTP صادر منه) لا تخضع للـ Outbound ACL المطبقة على منافذه!

إعداد سريع (انسخ والصق)

أمثلة شاملة لإنشاء Standard ACL لحماية خطوط الـ VTY، وإنشاء Extended Named ACL تسمح فقط بتصفح الويب والـ DNS:

! 1. تأمين الدخول عن بعد (VTY) عبر Standard ACL
access-list 10 remark "Allow only IT Admin PC to SSH/Telnet"
access-list 10 permit host 192.168.1.50
line vty 0 4
 access-class 10 in

! 2. إنشاء Extended Named ACL متقدمة
ip access-list extended FILTER-LAN
 remark "Allow DNS queries to external server"
 permit udp 192.168.1.0 0.0.0.255 host 8.8.8.8 eq 53
 remark "Allow Web browsing (HTTP/HTTPS)"
 permit tcp 192.168.1.0 0.0.0.255 any eq 80
 permit tcp 192.168.1.0 0.0.0.255 any eq 443
 remark "Allow return established TCP traffic"
 permit tcp any 192.168.1.0 0.0.0.255 established
 remark "Block everything else and log"
 deny ip any any log

! 3. تطبيق القائمة على المنفذ في اتجاه الدخول
interface GigabitEthernet0/0
 ip access-group FILTER-LAN in

الإعداد خطوة بخطوة

access-list (Standard Numbered) 1-99 & 1300-1999

Router(config)# Exam PT ✔

الصيغة:

access-list <1-99 | 1300-1999> {permit | deny} {<source-ip> <wildcard-mask> | host <source-ip> | any} [log]

أمثلة شائعة:

! السماح لجهاز واحد محدد (Host)
access-list 1 permit host 192.168.1.10
! أو بصيغة Wildcard mask:
access-list 1 permit 192.168.1.10 0.0.0.0

! السماح لشبكة فرعية كاملة (/24)
access-list 1 permit 192.168.1.0 0.0.0.255

! رفض شبكة معينة والسماح للباقي
access-list 1 deny 192.168.2.0 0.0.0.255
access-list 1 permit any

الشرح: الـ Standard ACL تطابق عنوان الـ Source فقط. كلمة host تعني مطابقة هذا الـ IP بالتمام والكمال (Wildcard Mask: 0.0.0.0). وكلمة any تعني أي عنوان (0.0.0.0 255.255.255.255).

access-list (Extended Numbered) 100-199 & 2000-2699

Router(config)# Exam PT ✔

الصيغة:

access-list <100-199 | 2000-2699> {permit | deny} <protocol> <source> <src-wildcard> [src-port] <destination> <dst-wildcard> [dst-operator dst-port] [established] [log]

البروتوكولات والمشغلات الشائعة:

  • <protocol>: إما ip (كل الحزم)، أو tcp، أو udp، أو icmp.
  • eq: يساوي (Equals) المنفذ المحدد.
  • neq: لا يساوي (Not Equals).
  • gt / lt: أكبر من / أقل من (Greater than / Less than).
  • range <start> <end>: نطاق من المنافذ (مثلاً: range 1024 65535).

أمثلة هامة للامتحان:

! منع جهاز معين من تصفح الويب على سيرفر محدد
access-list 101 deny tcp host 192.168.1.15 host 10.0.0.5 eq 80

! السماح بالبينج (ICMP Echo) من شبكة LAN للإنترنت
access-list 101 permit icmp 192.168.1.0 0.0.0.255 any echo

! السماح بالـ Ping Reply فقط الوارد من الخارج
access-list 101 permit icmp any 192.168.1.0 0.0.0.255 echo-reply

! السماح لجميع حزم الـ IP الأخرى
access-list 101 permit ip any any

ip access-list (Named ACLs) Modern Sub-mode Editing

Router(config)# & (config-ext-nacl)# Exam PT ✔

الصيغة:

! الدخول لوضع تعديل القائمة المسماة
ip access-list {standard | extended} <acl-name>

! داخل الوضع الفرعي (الأسطر ترقم تلقائياً 10, 20, 30...):
 [sequence-number] {permit | deny} ...
 remark <comment-text>

ميزة التعديل بأرقام الـ Sequence Numbers:

ip access-list extended SECURE-TRAFFIC
 10 permit tcp 192.168.1.0 0.0.0.255 any eq 443
 20 permit udp 192.168.1.0 0.0.0.255 any eq 53
 ! لحذف السطر 10 فقط بدون مسح القائمة كاملة:
 no 10
 ! لحشر سطر جديد بين 10 و 20:
 15 permit tcp 192.168.1.0 0.0.0.255 any eq 22

الشرح: القوائم المسماة (Named ACLs) هي الطريقة القياسية والحديثة الموصى بها، لأنها تتيح لك تسمية القائمة باسم وصفي واضح، وحذف أو إضافة أسطر معينة في منتصف القائمة باستخدام أرقام التسلسل (sequence-number) دون الحاجة لحذف القائمة وإعادة كتابتها من الصفر!

ip access-group Apply to Interface (in / out)

Router(config-if)# Exam PT ✔

الصيغة:

interface <interface-id>
 ip access-group <acl-name-or-number> {in | out}

الفرق الحاسم بين in و out:

  • in (Inbound): الحزمة يتم فحصها بمجرد دخولها للمنفذ وقبل أن ينظر الراوتر في جدول التوجيه (Routing Table). إذا تم رفضها، يتم إسقاطها فوراً ويوفر الراوتر مجهود معالجة التوجيه.
  • out (Outbound): الحزمة تدخل الراوتر أولاً، ويحدد الراوتر منفذ الخروج عبر جدول التوجيه، وقبل أن تخرج الحزمة من منفذ الخروج يتم فحصها بالـ ACL. إذا طابقت منعاً، تسقط.

access-class Apply to VTY Lines (Telnet / SSH)

Router(config-line)# Exam PT ✔

الصيغة:

line vty 0 4
 access-class <acl-name-or-number> in

الشرح: أحد أهم أسئلة امتحان الـ CCNA! لتحديد من يحق له الاتصال بالراوتر عن بعد عبر SSH أو Telnet، نطبق الـ ACL تحت خطوط الـ VTY باستخدام أمر access-class in وليس ip access-group. غالباً ما نستخدم هنا Standard ACL تحدد أجهزة مهندسي الشبكة فقط.

ip access-list resequence Reorder Sequence Numbers

Router(config)# PT ✔

الصيغة:

ip access-list resequence <acl-name> <starting-sequence> <step-interval>

مثال:

ip access-list resequence FILTER-LAN 10 10

الشرح: لو أضفت أسطر كثيرة بأرقام متقاربة (مثلاً 11, 12, 13) ولم يعد هناك مساحة لحشر أسطر جديدة، يقوم هذا الأمر بإعادة ترقيم القائمة كاملة لتبدأ من 10 وبفارق 10 بين كل سطر (10, 20, 30, 40...).

permit tcp ... established TCP Return Traffic Filtering

Router(config-ext-nacl)# Exam PT ✔

الصيغة:

permit tcp any <internal-network> <wildcard> established

الشرح: كلمة established تطابق حزم الـ TCP التي تحتوي على أعلام ACK أو RST في الترويسة. هذا يعني أن الحزمة هي جزء من اتصال قائم فتحه الجهاز الداخلي بالفعل، فيسمح الراوتر بدخول الرد من الإنترنت بينما يمنع أي حزمة خارجية تحاول بدء اتصال جديد (حزم SYN) من اختراق الشبكة.

أوامر التحقق والمراقبة

show access-lists Privileged EXEC

Router# Exam PT ✔

الشرح: يعرض جميع القوائم المبرمجة على الجهاز، وأرقام التسلسل، وعدد الحزم التي طابقت كل سطر (Hit Counts).

Router# show access-lists
Standard IP access list 10
    10 permit 192.168.1.50 (4 matches)
Extended IP access list FILTER-LAN
    10 permit udp 192.168.1.0 0.0.0.255 host 8.8.8.8 eq domain (125 matches)
    20 permit tcp 192.168.1.0 0.0.0.255 any eq www (450 matches)
    30 permit tcp 192.168.1.0 0.0.0.255 any eq 443 (890 matches)
    40 permit tcp any 192.168.1.0 0.0.0.255 established (1320 matches)
    50 deny ip any any log (14 matches)

ملاحظة امتحانية: عداد الـ (matches) مفيد جداً في فحص الأعطال؛ فإذا كان السطر لا يزيد فيه عدد الـ matches، فهذا يعني أن الترافيك لم يصل إليه أو تم إسقاطه بسطر يسبقه!

show ip interface Privileged EXEC

Router# Exam PT ✔

الشرح: للتأكد من ربط الـ ACL بالمنفذ واتجاه التطبيق (Inbound أو Outbound).

Router# show ip interface GigabitEthernet0/0
GigabitEthernet0/0 is up, line protocol is up
  Internet address is 192.168.1.1/24
  Inbound  access list is FILTER-LAN
  Outbound access list is not set

clear access-list counters Privileged EXEC

Router# PT ✔

الشرح: تصفير عدادات الـ Matches للبدء في اختبار ترافيك جديد من الصفر.

clear access-list counters [acl-name-or-number]

فحص الأعطال (Troubleshooting)

  • كل الاتصالات انقطعت تماماً بمجرد تطبيق الـ ACL:
    1. تذكر دائماً الرفض الضمني (Implicit Deny Any) في نهاية القائمة. إذا كانت القائمة تحتوي فقط على أسطر deny، فسيتم حظر كل شيء! أضف سطراً يسمح بباقي الترافيك (permit ip any any).
    2. تأكد من أن اتجاه التطبيق (in أو out) صحيح بالنسبة لمسار الحزم في الراوتر.
  • أحد الأسطر لا يعمل رغم صحته (0 matches):
    1. افحص ترتيب الأسطر؛ إذا كان هناك سطر عام يسبقه (مثلاً سطر permit any أو سطر يطابق شبكة أوسع)، فإن الراوتر يطبق السطر الأول فوراً ولا يصل للسطر الثاني إطلاقاً.
    2. القاعدة: ضع القواعد الأكثر تخصيصاً (Most Specific) في الأعلى، والقواعد العامة (General) في الأسفل.
  • الـ Wildcard Mask مكتوب بالخطأ كـ Subnet Mask:
    1. إذا كتبت 255.255.255.0 بدلاً من 0.0.0.255، فإن الراوتر قد يعترض أو يطابق نطاقات غير مقصودة تماماً! تأكد من طرح الـ Subnet Mask من 255.255.255.255.
  • الأجهزة لا تستطيع تصفح الويب رغم السماح بـ Port 80:
    1. لكي يعمل التصفح، يحتاج الجهاز أولاً إلى ترجمة اسم الموقع عبر الـ DNS (UDP 53)! إذا لم تكن قد سمحت بالـ DNS في القائمة، فلن يستطيع المتصفح فتح أي موقع باسمه.

أخطاء شائعة وفخاخ الامتحان

  • نطاقات أرقام الـ ACLs (حفظ إجباري للامتحان):
    النوع (Type) النطاق القياسي (Standard Range) النطاق الموسع (Expanded Range)
    Standard IPv4 1 - 99 1300 - 1999
    Extended IPv4 100 - 199 2000 - 2699
  • موضع كتابة المنفذ في Extended ACL:

    في Extended ACL، يتم وضع المنفذ (Port) بعد عنوان الوجهة Destination إذا كنت تريد فحص منفذ الخدمة التي يقصدها الجهاز (مثل السيرفر)، وليس بعد عنوان المصدر:

    ! صحيح (يطابق سيرفر الويب الوجهة):
permit tcp 192.168.1.0 0.0.0.255 any eq 80

! خطأ شائع (يطابق جهاز المصدر إذا كان المنفذ العشوائي لجهازه هو 80!):
permit tcp 192.168.1.0 0.0.0.255 eq 80 any
  • فخ الـ VTY: استخدام ip access-group بدلاً من access-class:

    على خطوط الـ VTY (line vty 0 4)، الأمر الصحيح هو access-class <acl> in. كتابة ip access-group غير مقبولة في الـ CLI تحت الـ Lines وتعتبر خطأً فادحاً في الامتحان.

  • ترافيك الراوتر الداخلي (Self-Originated Packets):

    لو وضعت Outbound ACL على منفذ الراوتر تمنع الـ Ping (deny icmp any any)، وقمت بعمل ping من الراوتر نفسه، سيعمل البينج بنجاح لأن ترافيك الراوتر نفسه لا يخضع للـ Outbound ACL على واجهاته!

  • أشهر أسماء المنافذ في الـ CLI:
    • www = 80 (HTTP)
    • 443 = HTTPS (سيسكو لا تستخدم كلمة https في أجهزة قديمة بل تكتب 443)
    • domain = 53 (DNS)
    • ssh = 22
    • telnet = 23
    • ftp = 21 (Control) و ftp-data = 20
    • echo = ICMP Ping Request و echo-reply = ICMP Ping Response

جدول مختصر

Command Mode الوظيفة (Purpose)
access-list <1-99> {permit|deny} <src> <wcard> Global config إنشاء Standard ACL رقمية تفلتر بناءً على عنوان المصدر فقط.
access-list <100-199> {permit|deny} <proto> <src> <dst> [port] Global config إنشاء Extended ACL رقمية تفلتر بالمصدر والوجهة والبروتوكول والمنافذ.
ip access-list {standard|extended} <name> Global config الدخول للوضع الفرعي لإنشاء وتعديل قائمة مسماة (Named ACL).
ip access-group <acl> {in | out} Interface config تطبيق القائمة على واجهة الراوتر أو السويتش في اتجاه الدخول أو الخروج.
access-class <acl> in Line config (vty) تأمين جلسات الدخول عن بعد (SSH/Telnet) بحصرها على أجهزة محددة.
ip access-list resequence <name> <start> <step> Global config إعادة ترتيب أرقام تسلسل القائمة المسماة لتوفير مساحات لإضافة قواعد جديدة.
show access-lists [name] Privileged EXEC عرض محتويات القوائم وعدد الحزم المطابقة (Hit Counts).
show ip interface <int> Privileged EXEC التحقق من ربط الـ ACL بالمنفذ واتجاه تطبيقها (Inbound / Outbound).
