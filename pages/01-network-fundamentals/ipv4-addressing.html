عناوين IPv4 وإعدادات المنافذ

نبذة سريعة

عشان الراوتر يقدر يوجه البيانات (Routing)، لازم كل منفذ (Interface) ياخد عنوان IPv4 مميز ويكون في شبكة مختلفة عن المنفذ التاني. الصفحة دي بتركز على إزاي تدي الـ IP للمنفذ سواء بشكل يدوي (Static) أو تخليه يسحب IP لوحده (DHCP Client).

ملاحظة: إعدادات الراوتر كـ DHCP Server نفسه (عشان يوزع هو IPs) موجودة في قسم الـ IP Services.

إعداد سريع (انسخ والصق)

الطريقة المعتادة لإعطاء IP لمنفذ وتفعيله:

interface g0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown

الإعداد خطوة بخطوة

ip address Interface config

Router(config-if)# Exam PT ✔

الصيغة:

ip address <ip-address> <subnet-mask>

إيه اللي بنحطه مكان القيم:

  • <ip-address> = عنوان الـ IP المخصص للمنفذ.
  • <subnet-mask> = قناع الشبكة بالشكل العادي المكون من 4 أرقام (زي 255.255.255.0)، مينفعش نكتبه بطريقة الـ Prefix (زي /24) هنا في أنظمة IOS التقليدية.

مثال:

R1(config)# interface g0/0
R1(config-if)# ip address 10.1.1.254 255.255.255.0
R1(config-if)# no shutdown

ip address dhcp Interface config

Router(config-if)# Exam PT ✔

الصيغة:

ip address dhcp

الشرح: بيخلي المنفذ يتصرف كأنه كمبيوتر عادي ويبعت طلب DHCP عشان يسحب IP بشكل أوتوماتيكي من السيرفر. بنستخدمه غالباً في المنفذ اللي واصل بالإنترنت (ISP).

مثال:

R1(config)# interface g0/1
R1(config-if)# ip address dhcp
R1(config-if)# no shutdown

secondary ip address Interface config

Router(config-if)# Exam PT ✔

الصيغة:

ip address <ip-address> <subnet-mask> secondary

الشرح: الطبيعي إن كل منفذ ليه شبكة واحدة. لو كتبت أمر ip address مرتين ورا بعض، الأمر التاني بيمسح الأولاني. لو عايز المنفذ يبقى جزء من شبكتين مختلفتين في نفس الوقت (مثلاً وقت نقل الشبكات)، لازم تحط كلمة secondary في آخر الأمر التاني.

مثال:

R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# ip address 10.0.0.1 255.255.255.0 secondary

أوامر التحقق

1. show ip interface brief

أهم أمر للتأكد إن الـ IP اتحط والمنفذ شغال، وبيوريك كمان الـ IP ده اتكتب يدوي (manual) ولا اتسحب أوتوماتيك (dhcp).

R1# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0     10.1.1.254      YES manual up                    up
GigabitEthernet0/1     192.168.5.10    YES dhcp   up                    up

2. show protocols

أمر سريع بيعرضلك كل المنافذ الشغالة ومعاها الـ IP والـ Subnet Mask بتاعها (بصيغة الـ Prefix زي /24)، وده ميزة مش موجودة في الأمر اللي فات.

R1# show protocols
Global values:
  Internet Protocol routing is enabled
GigabitEthernet0/0 is up, line protocol is up
  Internet address is 10.1.1.254/24
GigabitEthernet0/1 is up, line protocol is up
  Internet address is 192.168.5.10/24

فحص الأعطال (Troubleshooting)

رسالة Overlaps

لو حاولت تدي لمنفذ عنوان 10.0.0.2 255.0.0.0 وكان فيه منفذ تاني أصلاً واخد 10.1.1.1 255.0.0.0، الراوتر هيرفض ويطلعلك خطأ: % 10.0.0.0 overlaps with GigabitEthernet0/0. الراوتر مش بيسمح إن منفذين يكونوا في نفس الشبكة.

حالة Status up / Protocol down

لو الـ Status up معناه الكابل راكب وسليم كهربائياً (Layer 1 سليم). بس لو الـ Protocol down ده معناه فيه مشكلة في الطبقة التانية (Layer 2). الأسباب المعتادة:

  • نوع التغليف (Encapsulation) مختلف بين الطرفين (مثلاً واحد HDLC والتاني PPP على كابل سيريال).
  • مفيش نبضة وقت (Clock rate) مبعوتة على كابل السيريال القديم.
  • الـ Switch اللي إنت واصل عليه قافل المنفذ لأسباب أمنية (Port Security).

أخطاء شائعة وفخاخ الامتحان

  • عنوان الشبكة أو البرودكاست: لو حاولت تدي الراوتر أول IP في الشبكة (Network Address زي 192.168.1.0) أو آخر IP (Broadcast زي 192.168.1.255)، الراوتر هيطلعلك رسالة Bad mask ومش هيقبل الأمر. المنفذ لازم ياخد IP متاح للأجهزة (Host IP).
  • نسيان التفعيل: كتابة أمر ip address لوحده مش كفاية، المنفذ بيفضل مقفول لحد ما تكتب no shutdown.
  • إلغاء الـ IP: لو عايز تمسح الـ IP من منفذ، ادخل جواه واكتب no ip address.

جدول مختصر

Command الوظيفة (Purpose)
ip address <ip> <mask> إعطاء المنفذ عنوان ثابت (Static).
ip address dhcp جعل المنفذ يسحب عنوان تلقائياً.
ip address <ip> <mask> secondary إضافة عنوان ثاني لنفس المنفذ (نادر).
no ip address حذف العنوان من المنفذ.
show ip interface brief التحقق من العناوين وحالة المنافذ.
show protocols التحقق من العناوين وقناع الشبكة (Subnet Mask).
