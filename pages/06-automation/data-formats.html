صيغ البيانات وواجهات REST APIs (Data Formats)

نبذة سريعة

عند التعامل مع البرمجة وأتمتة الشبكات، تتواصل البرامج وسكربتات Python مع أجهزة الشبكة والمتحكمات عبر واجهات برمجية APIs تتبادل البيانات بصيغ نصية مهيكلة بدلاً من المخرجات النصية غير المنظمة لشاشات الـ CLI:

  • صيغ تسلسل البيانات (Serialization Formats):
    • JSON (JavaScript Object Notation): الصيغة الأكثر انتشاراً في واجهات REST APIs والمتحكمات. تعتمد على أزواج المفاتيح والقيم، وتستخدم الأقواس المعقوفة { } للكائنات (Objects) والأقواس المربعة [ ] للمصفوفات (Arrays).
    • XML (Extensible Markup Language): تعتمد على الوسوم المفتوحة والمغلقة <tag>...</tag> وتستخدم بكثرة في بروتوكول NETCONF.
    • YAML (YAML Ain't Markup Language): الصيغة الأسهل قراءة للبشر، تعتمد على المسافات البادئة (Indentation) بدون أقواس، وتستخدم بكثرة في ملفات Ansible Playbooks.
  • واجهات برمجة REST APIs:
    • تعتمد على بروتوكول HTTP / HTTPS وتتميز بأنها غير محتفظة بالحالة (Stateless) وقابلة للتخزين المؤقت (Cacheable).
    • تربط عمليات إدارة البيانات (CRUD) بأفعال بروتوكول الـ HTTP:
      • Create (إنشاء): يقابل فعل POST.
      • Read (قراءة واستعلام): يقابل فعل GET.
      • Update (تعديل كامل): يقابل فعل PUT (أو PATCH للتعديل الجزئي).
      • Delete (حذف): يقابل فعل DELETE.

أمثلة سريعة (انسخ وقارن)

مقارنة لنفس بيانات راوتر شبكة بالصيغ الثلاث JSON و XML و YAML، مع مثال طلب استعلام عبر cURL:

! 1. نفس البيانات بصيغة JSON
{
  "hostname": "R1-CORE",
  "loopback_ip": "10.0.0.1",
  "interfaces": ["GigabitEthernet0/0", "GigabitEthernet0/1"],
  "enabled": true
}

! 2. نفس البيانات بصيغة YAML (ملاحظة: المسافات البادئة إجبارية ويحظر استخدام Tab!)
hostname: R1-CORE
loopback_ip: 10.0.0.1
interfaces:
  - GigabitEthernet0/0
  - GigabitEthernet0/1
enabled: true

! 3. نفس البيانات بصيغة XML
<device>
  <hostname>R1-CORE</hostname>
  <loopback_ip>10.0.0.1</loopback_ip>
  <interfaces>
    <interface>GigabitEthernet0/0</interface>
    <interface>GigabitEthernet0/1</interface>
  </interfaces>
  <enabled>true</enabled>
</device>

! 4. استعلام REST API باستخدام cURL للحصول على بيانات راوتر عبر RESTCONF
curl -k -u "netops:CiscoPass123!" \
  -H "Accept: application/yang-data+json" \
  https://192.168.1.1/restconf/data/ietf-interfaces:interfaces

قواعد وتفاصيل الصيغ خطوة بخطوة

JSON Rules & Syntax CCNA Blueprint 6.7

Exam Core JSON Syntax

قواعد قراءة وتفسير كود الـ JSON للامتحان:

  • الأقواس المعقوفة { }: تمثل كائناً (Object أو Dictionary) يحتوي على أزواج من المفاتيح والقيم.
  • الأقواس المربعة [ ]: تمثل مصفوفة أو قائمة مرتبة (Array أو List) تحتوي على عناصر مفصولة بفواصل.
  • المفاتيح (Keys): يجب دائماً وأبداً أن تكون محاطة بعلامات تنصيص مزدوجة "key". لا يُقبل استخدام علامات التنصيص المفردة 'key' في JSON القياسي!
  • أنواع البيانات المسموح بها في القيم (Values):
    • String (نص): محاط بعلامات تنصيص مزدوجة مثل "GigabitEthernet0/1".
    • Number (رقم): رقم مجرد بدون علامات تنصيص مثل 1500 أو 3.14.
    • Boolean (قيمة منطقية): إما true أو false بأحرف صغيرة.
    • Null (فارغ): القيمة null بأحرف صغيرة.
    • Array أو Object: يمكن تضمين مصفوفة أو كائن داخل كائن آخر (Nested Structures).
  • الفواصل: تفصل بين العناصر بفواصل عادية , ولكن يحظر وضع فاصلة بعد آخر عنصر في القائمة أو الكائن (Trailing Comma) لأنها تسبب خطأ في المعالجة.

YAML Rules & Syntax Ansible & Automation

Exam Core YAML Syntax

قواعد كتابة وقراءة ملفات YAML:

  • يبدأ المستند اختيارياً بثلاث شرطات --- وينهى اختيارياً بثلاث نقاط ....
  • المسافات البادئة (Indentation): هي التي تحدد الهرمية والتبعية. يجب استخدام مسافات عادية (Spaces) ويحظر تماماً استخدام زر الـ Tab!
  • القوائم (Lists): يبدأ كل عنصر في القائمة بشرطة متبوعة بمسافة - .
  • أزواج المفاتيح والقيم: مفصولة بنقطتين متبوعتين بمسافة إلزامية key: value.
  • لا يشترط وضع علامات تنصيص حول النصوص إلا إذا كانت تحتوي على رموز خاصة أو فراغات.

REST API Concepts & CRUD CCNA Blueprint 6.5

Exam Core REST Architecture

بنية عنوان الـ REST API (URI Components):

https://sandboxdnac.cisco.com:443/dna/intent/api/v1/network-device?managementIpAddress=10.1.1.1
\___/   \___________________/ \__/ \____________________________/ \____________________________/
  |               |            |                 |                              |
Protocol       Hostname       Port             Path                      Query Parameters

ربط عمليات الـ CRUD بأفعال الـ HTTP والـ Idempotency:

  • GET (Read): استرجاع البيانات فقط. يعتبر Safe (لا يغير شيئاً على الخادم) ويعتبر Idempotent (تكرار الطلب 100 مرة يعطي نفس النتيجة بدون أضرار).
  • POST (Create): إنشاء مورد جديد على الخادم. ليس Idempotent (تكرار الطلب سينشئ موارد مكررة).
  • PUT (Replace/Update): استبدال المورد بالكامل. يعتبر Idempotent (تكرار إرسال نفس الملف المستبدل لن يغير النتيجة).
  • PATCH (Partial Update): تعديل جزئي على حقل معين في المورد.
  • DELETE (Delete): حذف المورد. يعتبر Idempotent (حذف المورد مرة كحذفه عدة مرات).

HTTP Response Status Codes REST API Responses

Exam Core HTTP Codes

فئات وأشهر رموز الاستجابة للامتحان:

  • 2xx Success (النجاح):
    • 200 OK: تم تنفيذ الطلب بنجاح وتم إرجاع البيانات المطلوبة.
    • 201 Created: تم إنشاء المورد الجديد بنجاح (غالباً رد على طلب POST).
    • 204 No Content: تم تنفيذ العملية بنجاح ولكن لا توجد بيانات لإرجاعها (غالباً رد على طلب DELETE).
  • 3xx Redirection (إعادة التوجيه):
    • 301 Moved Permanently: تم نقل الرابط بشكل دائم لمكان جديد.
  • 4xx Client Errors (أخطاء من طرف العميل):
    • 400 Bad Request: صياغة الطلب خاطئة (مثلاً كود JSON غير صالح أو به خطأ كتابي).
    • 401 Unauthorized: خطأ في تسجيل الدخول (اسم مستخدم أو توكن أو كلمة سر خاطئة أو مفقودة).
    • 403 Forbidden: المستخدم موثق وله حساب، ولكن ليس لديه الصلاحيات الكافية للوصول لهذا المورد.
    • 404 Not Found: الرابط أو المورد المستهدف غير موجود على الخادم.
    • 405 Method Not Allowed: الفعل غير مدعوم على هذا الرابط (مثلاً إرسال POST على رابط يدعم GET فقط).
  • 5xx Server Errors (أخطاء من طرف الخادم):
    • 500 Internal Server Error: تعطل في كود أو تطبيق الخادم.
    • 503 Service Unavailable: الخادم محمل بأكثر من طاقته أو تحت الصيانة المؤقتة.

Python Script: REST API Interaction Practical Automation

Exam Code Script

كود بايثون نموذجي باستخدام مكتبة requests لاستدعاء REST API وفك تشفير JSON:

import requests
import json

# عنوان الـ API وبيانات التحقق
url = "https://sandboxdnac.cisco.com/dna/intent/api/v1/network-device"
headers = {
    "Accept": "application/json",
    "X-Auth-Token": "YOUR_BEARER_TOKEN_HERE"
}

# إرسال طلب GET
response = requests.get(url, headers=headers, verify=False)

# فحص كود الاستجابة
if response.status_code == 200:
    devices = response.json()  # تحويل نص الـ JSON إلى كائن Python
    for device in devices["response"]:
        print(f"Device: {device['hostname']} | IP: {device['managementIpAddress']}")
else:
    print(f"Request failed with status code: {response.status_code}")

فحص الأعطال (Troubleshooting)

  • ظهور خطأ 400 Bad Request أثناء إرسال بيانات JSON:
    1. تأكد من عدم وجود فواصل زائدة بعد آخر عنصر في الكائن أو المصفوفة (Trailing Comma).
    2. تأكد من استخدام علامات تنصيص مزدوجة "key" وليس مفردة.
    3. تأكد من أن الكلمات المنطقية مكتوبة بأحرف صغيرة (true وليس True).
  • ملف الـ Ansible Playbook يفشل في العمل (YAML Syntax Error):
    1. افحص المسافات البادئة؛ تأكد من عدم استخدام زر الـ Tab إطلاقاً واستبدله بمسافتين عاديتين.
    2. تأكد من وجود مسافة بعد النقطتين key: value ومسافة بعد الشرطة - item.
  • ظهور خطأ 401 Unauthorized في طلبات الـ API:
    1. تأكد من أن الـ Bearer Token لم تنتهِ صلاحيته (Expired Token)؛ فخوادم مثل Cisco DNA Center تتطلب تجديد التوكن كل فترة (ساعة غالباً).
    2. تأكد من إرسال التوكن في الـ Header الصحيح: Authorization: Bearer <token> أو X-Auth-Token.

أخطاء شائعة وفخاخ الامتحان

  • فخ الـ Idempotence في أفعال HTTP:

    الفعل Idempotent يعني أنك إذا كررته عدة مرات بنفس المدخلات فإن حالة النظام تظل كما هي بدون تغيير إضافي. الأفعال الـ Idempotent هي: GET, PUT, DELETE, HEAD. بينما الفعل POST ليس Idempotent لأنه سينشئ عنصراً جديداً في كل مرة ينفذ فيها!

  • الفرق بين 401 و 403:
    • 401 Unauthorized: "أنت غير معروف لي" (مشكلة في إثبات الهوية أو كلمة المرور).
    • 403 Forbidden: "أنا أعرفك، ولكن ليس مصرحاً لك بدخول هذه الغرفة" (مشكلة في الصلاحيات Authorization).
  • JSON لا يدعم التعليقات:

    سؤال امتحاني مخادع: محاولة وضع تعليقات مثل // comment أو # comment داخل ملف JSON تجعل الملف غير صالح برمجياً (Invalid JSON)!
