أدوات إدارة الإعدادات (Ansible, Puppet, Chef)

نبذة سريعة

في شبكات المؤسسات الضخمة التي تحتوي على مئات الراوترات والسويتشات، يؤدي إدخال الإعدادات يدوياً إلى أخطاء بشرية وتفاوت في الإعدادات (Configuration Drift). أدوات Configuration Management تسمح بتعريف الحالة المطلوبة للشبكة كأكواد برمجية (Infrastructure as Code - IaC) وتطبيقها ومراقبتها تلقائياً وبشكل متكرر:

  • خاصية الـ Idempotency (خاصية التكرار الآمن):

    هي الميزة الأهم في أدوات الأتمتة؛ وتعني أن تشغيل كود الأتمتة مرة واحدة أو 100 مرة على نفس الجهاز سينتج دائماً نفس الحالة النهائية المضبوطة تماماً بدون إحداث أي تغييرات جانبية غير مقصودة وبدون تكرار الأوامر المطبقة بالفعل.

  • المقارنة الكلاسيكية لأدوات الأتمتة الثلاث للامتحان:
    • Ansible: لا يحتاج لتثبيت أي برامج عميلة على الراوترات (Agentless)، يعتمد على بروتوكول SSH العادي، يعمل بنموذج الدفع (Push Model)، ويستخدم صيغة YAML في كتابة الـ Playbooks. (هو الأداة الأكثر استخداماً وشعبية في شبكات سيسكو).
    • Puppet: يعتمد على برنامج عميل (Agent-based)، يعمل بنموذج السحب (Pull Model) عبر HTTPS، ويستخدم لغة خاصة مبنية على روبي تسمى Puppet DSL في كتابة الـ Manifests (.pp).
    • Chef: يعتمد على برنامج عميل (Agent-based)، يعمل بنموذج السحب (Pull Model) عبر HTTPS، ويستخدم لغة Pure Ruby في كتابة الـ Cookbooks والـ Recipes (.rb).

نموذج عملي لـ Ansible Playbook (انسخ وقارن)

مثال واقعي لملف جرد الأجهزة (Inventory) وملف Playbook مكتوب بصيغة YAML لإعداد الـ VLANs على سويتشات سيسكو تلقائياً:

! 1. ملف جرد الأجهزة المستهدفة (hosts.ini)
[switches]
switch1 ansible_host=192.168.1.11
switch2 ansible_host=192.168.1.12

[switches:vars]
ansible_network_os=cisco.ios.ios
ansible_user=netops
ansible_ssh_pass=CiscoSecurePass#2026
ansible_connection=network_cli

! 2. ملف الـ Playbook لتطبيق إعدادات الـ VLAN (configure_vlans.yml)
---
- name: Configure Corporate VLANs on Cisco Switches
  hosts: switches
  gather_facts: false

  tasks:
    - name: Ensure VLAN 10 and 20 are created and named
      cisco.ios.ios_vlans:
        config:
          - vlan_id: 10
            name: SALES_DEPT
            state: active
          - vlan_id: 20
            name: IT_OPERATIONS
            state: active
        state: merged

مقارنة الأدوات الثلاث ومصطلحاتها خطوة بخطوة

Ansible Architecture & Terms Agentless & Push Model

Exam Core Red Hat Ansible

بنية ومصطلحات Ansible للامتحان:

  • Control Node: جهاز لينكس مثبت عليه Ansible، وهو الجهاز الوحيد الذي يُكتب عليه الكود وتُنفذ منه الأوامر (لا يدعم نظام Windows كـ Control Node أصلي).
  • Managed Nodes: أجهزة الشبكة التي نتحكم فيها (مثل راوترات وسويتشات سيسكو). لا تتطلب تثبيت أي سوفتوير خاص (Agentless)؛ يكفي تفعيل SSH ووجود حساب مستخدم بصلاحيات Privilege 15.
  • Inventory: ملف نصي (بصيغة INI أو YAML) يحتوي على قائمة بأسماء وأيبيهات الأجهزة ومجموعاتها وبيانات تسجيل الدخول.
  • Playbook: ملف مكتوب بصيغة YAML يحتوي على المسرحية البرمجية (Plays) والمهام المطلوب تنفيذها (Tasks).
  • Modules: موديولات سيسكو المبرمجة بالبايثون التي تؤدي العمل الفعلي على الراوتر، مثل:
    • cisco.ios.ios_command: لتنفيذ أوامر الاستعلام (مثل show version).
    • cisco.ios.ios_config: لإرسال أسطر إعدادات وتعديل الـ Running-Config.
  • Push Model: جهاز الـ Control Node هو الذي يبدأ الاتصال ويدفع (Pushes) الأوامر فوراً للأجهزة دون انتظار.

Puppet Architecture & Terms Agent-based & Pull Model

Exam Core Puppet

بنية ومصطلحات Puppet للامتحان:

  • Puppet Master (Server): الخادم المركزي الذي يحتوي على الكود ومواصفات الحالة المستهدفة للشبكة.
  • Puppet Agent: برنامج يتم تثبيته على الأجهزة المُدارة (بالنسبة لسويتشات سيسكو Nexus/Catalyst يتم تشغيل Puppet Agent داخل حاوية Guest Shell أو عبر Puppet Device Proxy).
  • Pull Model: يقوم العميل (Agent) بطلب الإعدادات وسحبها (Pulls) من السيرفر بشكل دوري (افتراضياً كل 30 دقيقة).
  • Manifests: الملفات التي تحتوي على تعريف الحالة المرغوبة وتنتهي بامتداد .pp.
  • اللغة: مكتوبة بلغة Puppet DSL (Domain-Specific Language) المشابهة للغة روبي.
  • Facter: أداة مدمجة تجمع معلومات ومواصفات الجهاز (Facts كالـ MAC والـ IP وسعة الذاكرة) وترسلها للماستر.
  • بروتوكول النقل: تعتمد على تشفير HTTPS عبر منفذ TCP 8140.

Chef Architecture & Terms Cookbooks, Recipes & Ruby

Exam Core Progress Chef

بنية ومصطلحات Chef للامتحان (مصطلحات مستوحاة من الطهي والمطابخ):

  • Chef Workstation: حاسوب المهندس الذي يكتب ويطور عليه الأكواد ويختبرها قبل رفعها للسيرفر.
  • Chef Server: الخادم المركزي الذي يخزن الوصفات البرمجية والسياسات.
  • Chef Node / Client: الأجهزة المُدارة التي يعمل عليها برنامج chef-client.
  • Recipes (الوصفات): الملفات الأساسية المكتوبة بلغة Pure Ruby وتنتهي بامتداد .rb، وتحدد الموارد المطلوب تهيئتها.
  • Cookbooks (كتب الطهي): مجموعة منظمة تضم عدة Recipes وملفات ومكتبات معاً.
  • Ohai: أداة مدمجة تجمع مواصفات ومعلومات الجهاز (Facts) وترسلها للـ Chef Server.
  • Pull Model: الجهاز يتصل بالخادم دورياً ويسحب (Pulls) التحديثات عبر HTTPS منفذ 443 أو 10002.

SaltStack (Salt) Master & Minions

Exam SaltStack

نظرة سريعة على SaltStack:

  • Salt Master: السيرفر المركزي للتحكم.
  • Salt Minions: البرامج العميلة المثبتة على الأجهزة (ويدعم أيضاً وضع Salt-SSH بدون عميل).
  • بروتوكول الاتصال: يعتمد على مكتبة ZeroMQ فائقة السرعة على منافذ TCP 4505 & 4506.
  • Model: يدعم كلا النموذجين: Push و Pull.
  • الصيغة: ملفات State Files (.sls) مكتوبة بصيغة YAML.

Terraform (IaC Framework) Declarative Infrastructure as Code

Exam Core (v1.1) HashiCorp Terraform

بنية ومفاهيم Terraform للامتحان:

  • Infrastructure as Code (IaC): أداة رائدة لبناء وإدارة البنية التحتية السحابية والشبكية كأكواد برمجية معلنة (Declarative).
  • اللغة المستخدمة: لغة HCL (HashiCorp Configuration Language) بملفات تنتهي بـ .tf.
  • ملف الحالة (State File - terraform.tfstate): الملف الذي يسجل فيه Terraform الحالة الفعلية لكل الموارد المنشأة للمقارنة ومنع التكرار (Idempotency).
  • مراحل التشغيل الأربعة:
    • terraform init: تجهيز بيئة العمل وتحميل الـ Providers (مثل موفر Cisco IOS XE أو AWS).
    • terraform plan: فحص الكود ومقارنته بملف الحالة وعرض التغييرات المزمع تنفيذها بدون تطبيقها فعلياً.
    • terraform apply: تنفيذ الأوامر وبناء الموارد فعلياً على الأجهزة والسحابة.
    • terraform destroy: حذف كل الموارد التي تم إنشاؤها عبر الكود بضغطة واحدة.

Git Version Control Basics DevOps for NetOps

Exam Core (v1.1) Version Control

أهم أوامر Git الأساسية لمهندس الشبكات:

  • git init: إنشاء مستودع Git محلي جديد لتتبع ملفات الإعدادات والـ Playbooks.
  • git clone <url>: نسخ مستودع كامل من منصة سحابية (مثل GitHub أو GitLab) لجهازك المحلي.
  • git status: فحص حالة الملفات ومعرفة ما تم تعديله أو إضافته.
  • git add <file>: نقل التعديلات لمرحلة التجهيز (Staging Area).
  • git commit -m "message": تسجيل نقطة حفظ للتعديلات مع رسالة توضيحية.
  • git push: رفع التعديلات المحفوظة من جهازك المحلي للمستودع السحابي البعيد (Remote Repository).
  • git pull: سحب أحدث التعديلات التي قام بها زملاؤك في الفريق ودمجها محلياً.
  • git branch <branch-name>: إنشاء فرع مستقل لتجربة إعدادات شبكة جديدة دون التأثير على الفرع الرئيسي (main).

فحص الأعطال (Troubleshooting)

  • أوامر الـ Ansible تفشل بالاتصال بالراوتر (SSH Failure):
    1. تأكد من إمكانية الوصول إلى بورت TCP 22 من جهاز الـ Control Node للراوتر.
    2. تأكد من صحة بيانات الدخول في ملف الـ Inventory، وأن حساب المستخدم يمتلك صلاحيات privilege 15.
    3. تأكد من ضبط خيار ansible_connection=network_cli و ansible_network_os=cisco.ios.ios في إعدادات المتغيرات.
  • فشل عملاء Puppet أو Chef في سحب التحديثات (Pull Failed):
    1. تأكد من فتح منافذ الـ HTTPS (TCP 8140 للـ Puppet و TCP 443 للـ Chef).
    2. تأكد من دقة مزامنة الوقت عبر NTP؛ لأن الشهادات الرقمية (SSL Certificates) تفشل فوراً إذا كان توقيت العميل مختلفاً عن توقيت السيرفر!

أخطاء شائعة وفخاخ الامتحان

  • فخ Push مقابل Pull:

    تذكر دائماً: Ansible هو الأداة الوحيدة المشهورة التي تدفع الأوامر (Push) ولا تتطلب برنامج عميل (Agentless). بينما Puppet و Chef كلاهما يسحب التحديثات (Pull) وكلاهما يتطلب عميلاً (Agent-based).

  • الربط بين أسماء الملفات والأدوات:
    • لو شفت في السؤال كلمة Playbook أو Inventory ← الإجابة Ansible.
    • لو شفت في السؤال كلمة Manifest أو Facter ← الإجابة Puppet.
    • لو شفت في السؤال كلمة Cookbook أو Recipe أو Ohai ← الإجابة Chef.
  • مفهوم الـ Idempotence في الأتمتة:

    إذا كانت الأداة Idempotent ونفذت Playbook ينشئ VLAN 10، وكانت VLAN 10 موجودة بالفعل على السويتش، فإن الأداة لن تفعل أي شيء ولن تعيد كتابة الأمر، بل ستسجل أن الحالة OK / Unchanged فقط.
