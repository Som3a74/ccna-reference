Routing Fundamentals (أساسيات التوجيه)

نبذة سريعة

التوجيه (Routing) هو عملية اختيار أفضل مسار لنقل البيانات من شبكة لأخرى. الراوتر بيبني جدول توجيه (Routing Table) عشان يعرف يوصل للشبكات المختلفة. المسارات ممكن تكون متصلة مباشرة (Connected/Local)، أو مكتوبة يدوياً (Static)، أو متعلمة ديناميكياً عن طريق بروتوكولات التوجيه زي OSPF.

إعداد سريع (انسخ والصق)

إعداد مسار ثابت (Static Route) ومسار افتراضي (Default Route):

Router(config)# ip route 192.168.2.0 255.255.255.0 10.1.1.2
Router(config)# ip route 0.0.0.0 0.0.0.0 10.1.1.2
Router(config)# ip route 192.168.2.0 255.255.255.0 10.1.1.3 50

الإعداد خطوة بخطوة

ip route (Static Route) Config mode

Router(config)# Exam PT ✔

الصيغة:

ip route <destination_network> <subnet_mask> <next_hop_ip | exit_interface>

الشرح: بيستخدم لإضافة مسار ثابت يدوياً لشبكة معينة. بتحدد الشبكة الهدف (Destination)، قناع الشبكة (Subnet Mask)، وعنوان الراوتر اللي بعدك (Next-hop IP) أو اسم الفتحة اللي هتخرج منها (Exit Interface).

ip route 0.0.0.0 0.0.0.0 (Default Route) Config mode

Router(config)# Exam PT ✔

الصيغة:

ip route 0.0.0.0 0.0.0.0 <next_hop_ip | exit_interface>

الشرح: المسار الافتراضي (Default Route) بيستخدم عشان الراوتر يبعت أي بيانات لشبكة مش موجودة عنده في الـ Routing Table للمسار ده. بيعتبر "Gateway of Last Resort".

Floating Static Route Config mode

Router(config)# Exam PT ✔

الصيغة:

ip route <destination_network> <subnet_mask> <next_hop_ip> <AD>

الشرح: مسار ثابت احتياطي. بتضيف له Administrative Distance (AD) أعلى من المسار الأساسي. مش بيظهر في جدول التوجيه إلا لو المسار الأساسي وقع.

مفاهيم التوجيه الأساسية (كيف يختار الراوتر المسار؟)

عشان الراوتر يقرر يبعت الداتا في أي طريق، بيمشي على 3 قواعد بالترتيب:

  1. الأطابق الأطول (Longest Prefix Match): دي القاعدة الأهم على الإطلاق. الراوتر بيفضل المسار اللي فيه تطابق أكتر في الـ Subnet Mask. يعني مسار /26 هيكسب مسار /24 لنفس الـ IP، بغض النظر عن أي حاجة تانية.
  2. المسافة الإدارية (Administrative Distance - AD): لو الراوتر عنده مسارين لنفس الشبكة وبنفس الـ Mask بس من بروتوكولين مختلفين (مثلاً OSPF و Static)، هيختار صاحب الـ AD الأقل. الـ Static (1) بيكسب الـ OSPF (110).
  3. المعيار (Metric): لو المسارين من نفس البروتوكول (مثلاً طريقين OSPF)، الراوتر بيختار المسار صاحب الـ Metric الأقل (التكلفة الأقل).

الشرح: بيعمل فلترة لجدول التوجيه عشان يعرض فقط المسارات الثابتة (Static Routes) والمسار الافتراضي (Gateway of Last Resort S*) اللي تم تكوينها يدوياً. مفيد جداً للتأكد من صحة مسارات الـ Static والتأكد من ظهور المسارات الاحتياطية (Floating Static).

فحص الأعطال (Troubleshooting)

  • المسار الثابت مش بيظهر في جدول التوجيه: تأكد إن الفتحة (Interface) اللي متوصلة بـ Next-hop شغالة (Up/Up)، لأن الراوتر مش هيحط المسار في الجدول لو مفيش اتصال فيزيائي سليم.
  • Floating Static Route مش شغال وقت العطل: تأكد إن الـ AD اللي اديته للمسار الاحتياطي أعلى من الـ AD بتاع المسار الأساسي (مثلاً أعلى من 1 لو كان الأساسي Static، أو أعلى من 110 لو كان OSPF).
  • مشكلة الـ Next-hop Reachability: لو الـ Next-hop مش في نفس الشبكة المتصلة بيك مباشرة، الراوتر لازم يكون عنده مسار يقدر يوصل بيه للـ Next-hop ده (ويعرف بـ Recursive Routing).
  • استخدام Exit Interface في شبكات الـ Ethernet: لو عملت مسار ثابت باستخدام اسم الفتحة (زي ip route 10.0.0.0 255.0.0.0 G0/0) على شبكة Ethernet، الراوتر هيبعت ARP Request لكل IP بيحاول يكلمه في الشبكة دي. ده بيعمل حمل كبير جداً وممكن يفشل لو الراوتر اللي قدامك قافل الـ Proxy ARP. دايماً استخدم الـ Next-hop IP.

أخطاء شائعة وفخاخ الامتحان

  • الخلط بين C و L في جدول التوجيه: الحرف C معناه الشبكة بالكامل (Connected Route)، بينما الحرف L معناه الـ IP الخاص بالراوتر نفسه على الفتحة دي (Local Route) وبيكون بـ subnet mask /32.
  • Administrative Distance (AD): لازم تكون حافظ قيم الـ AD الأساسية للامتحان:
    • Connected: 0
    • Static: 1
    • eBGP: 20
    • EIGRP: 90
    • OSPF: 110
    • IS-IS: 115
    • RIP: 120
  • Fully Specified Static Route: في الامتحان ممكن يطلب منك مسار محدد بالكامل. معناه إنك تكتب الـ exit interface والـ next-hop IP في نفس الأمر: ip route 192.168.1.0 255.255.255.0 G0/0 10.1.1.2.
