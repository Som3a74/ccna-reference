CCNA Reference

بروتوكول OSPFv2 (منطقة واحدة - Single Area)

نبذة سريعة

بروتوكول OSPF هو بروتوكول توجيه ديناميكي من نوع Link-State. بيستخدم خوارزمية Dijkstra (SPF) عشان يختار أسرع مسار للشبكات بناءً على التكلفة (Cost). النسخة التانية (OSPFv2) مخصصة لشبكات IPv4. في الـ CCNA بنركز على إعداد وتأمين منطقة واحدة وهي Area 0 (الـ Backbone).

إعداد سريع (انسخ والصق)

لتشغيل OSPF وإعلان شبكتين على راوتر R1:

R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
R1(config-router)# network 192.168.10.0 0.0.0.255 area 0
R1(config-router)# passive-interface g0/1

الإعداد خطوة بخطوة

router ospf Global config

Router(config)# Exam PT ✔

الصيغة:

router ospf <process-id>

إيه اللي بنحطه مكان القيم:

  • <process-id> = رقم الـ process محلي على الراوتر (من 1 إلى 65535). مش شرط يكون متطابق بين الرواتر عشان يشتغلوا مع بعض.

الشرح: بيفعّل بروتوكول OSPF ويدخلك على وضع الإعداد الخاص بيه.

مثال:

R1(config)# router ospf 1
R1(config-router)#

شرح المثال بالعربي: بنشغل OSPF برقم 1.

للتأكد: show ip protocols

router-id Router config

Router(config-router)# Exam PT ✔

الصيغة:

router-id <ip-address>

إيه اللي بنحطه مكان القيم:

  • <ip-address> = اسم أو رقم تعريفي للراوتر في شكل IP (مثلًا: 1.1.1.1).

الشرح: بيحدد هوية الراوتر في شبكة OSPF. لو ما عملتوش، الراوتر بيختار أعلى IP للـ Loopback، ولو مفيش بيختار أعلى IP لـ Interface شغالة.

مثال:

R1(config-router)# router-id 1.1.1.1

شرح المثال بالعربي: بنحدد إن اسم الراوتر في OSPF هو 1.1.1.1.

للتأكد: show ip protocols

انتبه: لو غيرت الـ router-id بعد ما OSPF اشتغل، هتحتاج تعمل clear ip ospf process عشان التغيير يتطبق.

network ... area Router config

Router(config-router)# Exam PT ✔

الصيغة:

network <ip-address> <wildcard-mask> area <area-id>

إيه اللي بنحطه مكان القيم:

  • <ip-address> = عنوان الشبكة أو عنوان الـ Interface نفسها.
  • <wildcard-mask> = الماسك العكسي اللي بيحدد أي جزء من الـ IP لازم يتطابق.
  • <area-id> = رقم المنطقة (في الـ CCNA غالباً بتكون 0).

الشرح: بيحدد أي Interfaces هتشتغل OSPF وتاخد أرقام الشبكات بتاعتها تبلغها لباقي الرواتر. تقدر تكتب عنوان الشبكة مع الماسك العكسي بتاعها، أو تكتب الـ IP بتاع الـ Interface نفسها وتستخدم ماسك أصفار.

مثال:

R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
R1(config-router)# network 192.168.10.1 0.0.0.0 area 0

شرح المثال بالعربي: السطر 1 بيفعل OSPF على أي interface في شبكة 10.0.12.0/30. السطر 2 بيفعل OSPF على الـ interface اللي واخدة الـ IP بالظبط (192.168.10.1).

للتأكد: show ip ospf interface brief

passive-interface Router config

Router(config-router)# Exam PT ✔

الصيغة:

passive-interface { <interface> | default }

إيه اللي بنحطه مكان القيم:

  • <interface> = اسم المنفذ (مثلًا: g0/1).
  • default = يخلي كل المنافذ passive بشكل افتراضي.

الشرح: بيمنع الراوتر إنه يبعت رسايل OSPF Hello من الـ Interface دي، فبالتالي مفيش علاقة OSPF (Neighbor) هتتبني هنا، لكن في نفس الوقت شبكة الـ Interface دي هتفضل مُعلنة في OSPF. بنستخدمها عادةً مع الـ Interfaces اللي واصلة بالـ LAN (الـ Switches والأجهزة) عشان الأمان وتقليل الزحمة.

مثال:

R1(config-router)# passive-interface g0/1

شرح المثال بالعربي: بنمنع رسايل OSPF تخرج من g0/1.

للتأكد: show ip protocols (بتظهر في قسم Passive Interfaces).

انتبه: لو عملت passive-interface لمنفذ واصل براوتر تاني، العلاقة هتقع فوراً.

default-information originate Router config

Router(config-router)# Exam PT ✔

الصيغة:

default-information originate [always]

إيه اللي بنحطه مكان القيم:

  • always = (اختياري) يخلي الراوتر يبعت الـ Default Route حتى لو هو شخصياً معندوش واحد.

الشرح: بيخلي الراوتر يبلغ كل الرواتر التانية في OSPF بالـ Default Route بتاعه (يعني طريق الإنترنت). لازم يكون الراوتر ده متبرمج عليه Default Route أصلاً.

مثال:

R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
R1(config)# router ospf 1
R1(config-router)# default-information originate

شرح المثال بالعربي: عملنا Default Route الأول، وبعدين دخلنا OSPF وقلنا له يوزعه للكل.

للتأكد: باقي الرواتر هتشوف المسار ده في show ip route ospf بـ رمز O*E2.

auto-cost reference-bandwidth Router config

Router(config-router)# Exam PT ✔

الصيغة:

auto-cost reference-bandwidth <megabits>

إيه اللي بنحطه مكان القيم:

  • <megabits> = السرعة المرجعية بالميجابت (مثلاً: 1000 لسرعة 1 جيجا، 10000 لسرعة 10 جيجا).

الشرح: OSPF بيحسب التكلفة (Cost) بقسمة القيمة المرجعية على سرعة اللينك. الافتراضي هو 100 ميجابت. فكده لو عندك لينك 1 جيجا ولينك 100 ميجا، OSPF هيشوفهم نفس التكلفة (Cost = 1). الأمر ده بيعدل القيمة عشان يقدر يفرق السرعات العالية.

مثال:

R1(config-router)# auto-cost reference-bandwidth 1000

شرح المثال بالعربي: بنغير القيمة عشان تكون 1 جيجابِت (1000 ميجا).

انتبه: لازم تغير القيمة دي على كل الرواتر في الشبكة عشان الحسابات تطلع مظبوطة ومفيش لوب (Loop) يحصل.

ip ospf cost Interface config

Router(config-if)# Exam PT ✔

الصيغة:

ip ospf cost <value>

إيه اللي بنحطه مكان القيم:

  • <value> = رقم التكلفة من 1 لـ 65535.

الشرح: بيخليك تفرض تكلفة معينة للـ Interface بشكل يدوي بدل ما OSPF يحسبها بناءً على السرعة (Bandwidth). مفيد جداً لهندسة مسارات الشبكة.

مثال:

R1(config)# interface g0/0
R1(config-if)# ip ospf cost 50

شرح المثال بالعربي: خلينا تكلفة مسار g0/0 تساوي 50.

للتأكد: show ip ospf interface g0/0

ip ospf hello-interval / dead-interval Interface config

Router(config-if)# Exam PT ✔

الصيغة:

ip ospf hello-interval <seconds>
ip ospf dead-interval <seconds>

إيه اللي بنحطه مكان القيم:

  • <seconds> = الوقت بالثواني. الافتراضي للـ Hello هو 10 ثواني، وللـ Dead هو 40 ثانية.

الشرح: بيغير أوقات رسايل OSPF. الـ Hello هو كل كام ثانية هيبعت رسالة جاره. الـ Dead هو الوقت اللي هيصبره على جاره لو مبعتش Hello قبل ما يعتبره وقع من الشبكة.

مثال:

R1(config)# interface g0/0
R1(config-if)# ip ospf hello-interval 5
R1(config-if)# ip ospf dead-interval 20

شرح المثال بالعربي: سرّعنا التوقيتات للنص عشان نكتشف الأعطال أسرع.

انتبه: عشان علاقة الجيرة (Adjacency) تقوم، لازم أوقات Hello و Dead تكون متطابقة بين الراوترين!

ip ospf priority Interface config

Router(config-if)# Exam PT ✔

الصيغة:

ip ospf priority <value>

إيه اللي بنحطه مكان القيم:

  • <value> = من 0 إلى 255. (الافتراضي 1، و0 معناه إنه أبداً مش هيبقى DR أو BDR).

الشرح: بنستخدمه في شبكات Ethernet عشان نتحكم مين الراوتر اللي هيبقى هو الريس (DR). الراوتر اللي أولويته أعلى بيكسب.

مثال:

R1(config)# interface g0/0
R1(config-if)# ip ospf priority 200

شرح المثال بالعربي: عليّنا أولوية R1 على المنفذ ده لـ 200 عشان نضمن إنه يفوز في انتخابات الـ DR.

ip ospf network point-to-point Interface config

Router(config-if)# Exam PT ✔

الصيغة:

ip ospf network point-to-point

الشرح: لو وصلنا راوترين بكابل Ethernet مباشر (ومفيش أي رواتر تانية معاهم)، OSPF بيفترض إن دي شبكة Broadcast وبيعمل انتخابات DR/BDR وبياخد وقت زيادة. الأمر ده بيقوله دي وصلة مباشرة ومفيش حد معانا، فبيلغي الانتخابات وبيسرع بناء العلاقة (Adjacency).

مثال:

R1(config)# interface g0/0
R1(config-if)# ip ospf network point-to-point

شرح المثال بالعربي: ألغينا انتخابات DR/BDR على المنفذ ده.

maximum-paths Router config

Router(config-router)# Exam PT ✔

الصيغة:

maximum-paths <number>

إيه اللي بنحطه مكان القيم:

  • <number> = عدد المسارات المسموح بيها (الافتراضي عادة 4).

الشرح: لو فيه مسارين ليهم نفس التكلفة بالضبط للوصول لنفس الشبكة، OSPF هيستخدمهم هما الاتنين (Load Balancing). الأمر ده بيحدد الحد الأقصى للمسارات المتساوية اللي يقدر يستخدمها في نفس الوقت.

مثال:

R1(config-router)# maximum-paths 2

أوامر التحقق

1. show ip ospf neighbor

أهم أمر عشان تتأكد إن الرواتر شافت بعضها وبقوا جيران.

R1# show ip ospf neighbor

Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           1   FULL/BDR        00:00:36    10.0.12.2       GigabitEthernet0/0
3.3.3.3           0   FULL/ -         00:00:32    10.0.13.3       GigabitEthernet0/1
  • Neighbor ID: هو الـ Router-ID بتاع الجار.
  • State: لو مكتوب FULL، معناه العلاقة اكتملت وممتازة. لو مكتوب 2WAY، دي طبيعية بين رواتر DROTHER.
  • Dead Time: الوقت المتبقي قبل ما الجار يعتبر واقع لو مبعتش Hello.

2. show ip ospf interface brief

بيوريك OSPF شغال على أي منافذ بالظبط، والتكلفة بتاعتها وحالة DR/BDR.

R1# show ip ospf interface brief
Interface    PID   Area            IP Address/Mask    Cost  State Nbrs F/C
Gi0/0        1     0               10.0.12.1/30       10    DR    1/1
Gi0/1        1     0               10.0.13.1/30       10    P2P   1/1

3. show ip protocols

بيأكد الـ Process ID، الـ Router ID، الشبكات اللي متعملها Network، والـ Passive Interfaces.

4. show ip route ospf

بيعرض بس المسارات اللي اتعلمها عن طريق OSPF.

R1# show ip route ospf
O    192.168.20.0/24 [110/20] via 10.0.12.2, 00:05:12, GigabitEthernet0/0
  • O: معناها مسار OSPF.
  • [110/20]: الـ 110 هي الـ Administrative Distance للـ OSPF، والـ 20 هي الـ Cost الكلية للمسار ده.

فحص الأعطال

الجار مبيظهرش؟ (Why won't my OSPF neighbor come up?)

لو عملت show ip ospf neighbor وملقتش الجار، راجع القائمة دي بالترتيب:

  1. هل الـ Interfaces شغالة وفي نفس الـ Subnet؟ (اعمل Ping).
  2. هل حطيت نفس رقم الـ Area في الناحيتين؟
  3. هل أرقام الـ Timers (Hello/Dead) متطابقة في الناحيتين؟
  4. هل الـ Router ID مختلف في كل راوتر؟ (لو متطابقين، مش هيشوفوا بعض).
  5. هل عملت passive-interface بالغلط على المنفذ اللي واصل بالجار؟
  6. هل فيه Authentication (باسوورد) مطلوبة ونسيتها أو كتبتها غلط؟
  7. هل الـ MTU متطابق على الناحيتين؟ (لو مش متطابق، العلاقة هتعلق في مرحلة EXSTART).
  8. هل الـ Network Type متطابق؟ (لو واحد Point-to-point والتاني Broadcast، مش هيشتغلوا صح).

مراحل علاقة الجيرة (OSPF States)

State المعنى بالعربي
Down مفيش أي Hello وصل من الجار ده.
Init الراوتر استلم Hello من الجار، بس لسة اسمه مش موجود فيها.
2-Way الاتصال شغال في الاتجاهين. هنا بتحصل انتخابات DR/BDR لو نوع الشبكة Broadcast.
ExStart بيتفقوا مين الماستر ومين العبد (عشان تبادل البيانات) وبيتفقوا على الـ Sequence Number. لو وقف هنا، غالباً مشكلة MTU.
Exchange بيتبادلوا الفهرس بتاع قواعد البيانات (DBD).
Loading بيطلبوا التفاصيل الناقصة وبيبعتوها لبعض (LSR و LSU).
Full قواعد البيانات بقت متطابقة 100%. دي الحالة المثالية.

قواعد انتخاب الـ DR / BDR

على شبكات الـ Ethernet بس، OSPF بينتخب راوتر رئيسي (Designated Router - DR) وراوتر احتياطي (BDR). باقي الرواتر بتكون DROTHER.

  1. الراوتر صاحب أعلى أولوية Priority بيكسب الـ DR (الافتراضي 1).
  2. لو الأولويات متساوية، بيبصوا على الـ Router ID (الأعلى بيكسب).
  3. لو عملت الـ Priority = 0، الراوتر ده مستحيل يبقى DR ولا BDR أبداً.

أخطاء شائعة وفخاخ الامتحان

  • الـ Wildcard Mask مش السابنت ماسك! الـ 255 بتبقى 0 والـ 0 بيبقى 255. (مثال: /24 بيبقى 0.0.0.255).
  • لو استخدمت network، لازم تتأكد إن الـ IP بتاع الـ Interface بيقع جوة الـ Range اللي كتبته. أسهل طريقة في العملي إنك تكتب الـ IP بتاع الـ Interface بالظبط مع ماسك 0.0.0.0.
  • تنسى إن انتخابات الـ DR مش بتتعاد (No preemption). لو الراوتر الرئيسي وقع والاحتياطي مسك مكانه، ورجع الرئيسي اشتغل تاني، الاحتياطي هيفضل هو الريس لحد ما تعمله ريستارت بـ clear ip ospf process.
  • لو كتبت default-information originate والراوتر أصلاً معلوش مسار 0.0.0.0 0.0.0.0، الأمر مش هيعمل أي حاجة ومش هيعلن Default Route.

جدول مختصر

Command الوظيفة (Purpose)
router ospf <id> تفعيل OSPF.
router-id <ip> تحديد اسم الراوتر في OSPF.
network <ip> <wildcard> area 0 تحديد الـ Interfaces اللي هتشتغل.
passive-interface <int> منع إرسال رسايل OSPF على منفذ معين للعملاء.
default-information originate توزيع الـ Default Route للرواتر التانية.
auto-cost reference-bandwidth 1000 ضبط التكلفة عشان تتناسب مع سرعات الجيجا واكتر.
show ip ospf neighbor التأكد من الجيران وحالتهم (Full).
